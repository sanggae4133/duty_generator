# 설계 철학

무엇을 왜 이렇게 만들었는지. 새 기능을 넣거나 구조를 바꿀 때 이 원칙에 맞는지 먼저 본다. 지금 코드의 모양은 [ARCHITECTURE.md](ARCHITECTURE.md).

## 원칙

### 1. 운영은 단순하게

관리자 1~2명이 다른 업무와 함께 돌리는 서비스다. 장애가 나도 처음 보는 사람이 README 와 [OPERATIONS.md](OPERATIONS.md)만 보고 고칠 수 있어야 한다.

- 서버 한 대, 프로세스 두 개(웹·작업자), systemd 유닛 두 개.
- 설정은 루트 `.env` 하나. 개발 PC 와 서버의 차이는 이 파일의 값뿐이다.
- 실행 중 생기는 파일(DB·백업·로그·잠금)은 `data/` 하나.
- 셸 스크립트·타이머·logrotate·셸 함수를 만들지 않는다. 반복 작업은 `manage.py` 명령과 작업자 한 프로세스 안에.
- 명령은 그대로 복사해 쓸 수 있게 적는다.

### 2. 필요한 만큼만 만든다

- 지금 필요한 것만. "나중에 쓸지도"는 나중에 만든다.
- 표준 라이브러리 → 이미 쓰는 라이브러리 → 직접 작성 순서로 고른다. 라이브러리를 늘리기 전에 몇 줄로 되는지 본다.
- 빌드 단계가 없다: 화면은 Django 템플릿 + Pico.css + htmx(파일로 직접 서빙, CDN 없음). `npm install` 이 필요 없다.
- 쓰지 않게 된 기능은 지운다(예전 시트 가져오기, 외부 API, 예전 DB 변환 명령, 데이터 구조 화면).

### 3. 규칙은 한 곳에, 기록은 남긴다

- DB 를 바꾸는 규칙(권한, 지난 날짜, 변경 기록, 상태 기록)은 전부 `duty/services/`를 거친다. 화면·명령은 서비스만 부른다.
- 계산은 DB 없이 하는 순수 함수로(장중관제 생성, CSV, 알림 계획, 캘린더 글자). 그래서 빠르고 정확하게 테스트한다.
- 근무 변경·회차 상태 변경은 지우지 않는 기록으로 남긴다. 기록이 걸린 사람·회차는 지울 수 없다(`PROTECT`). 퇴사자는 지우지 않고 재직을 끈다.
- 정해진 값만 받는 칸은 앱 검사와 DB 제약을 둘 다 건다(앱을 거치지 않은 쓰기도 막게).
- 동시에 고치면 먼저 저장한 쪽이 이긴다. 서비스는 트랜잭션 안에서 상태를 다시 읽어 확인한다.

### 4. 되돌릴 수 있게

- 배포는 덮어쓴 행을 보관해 두고 배포 취소로 되살린다(가장 최근 배포부터 차례로).
- 작업자가 매일 DB 를 백업한다. 업그레이드 전에는 손으로 한 번 더. 복원은 명령 하나.
- 지우는 동작은 확인창을 거치고, 화면 맨 아래 "위험 구역"에 둔다.

### 5. 개인정보와 비밀은 최소로

- 실명은 저장소·테스트·로그·문서에 넣지 않는다. 사용법 영상도 가짜 데이터로 찍는다.
- 비밀값은 필요한 만큼만 둔다: 캘린더 구독 토큰은 해시만 저장한다. 봇 토큰·푸시 개인키는 보내는 데 필요해 DB 에 원문으로 두지만(백업에도 들어간다) 화면에는 끝 4자리만, 로그·메시지에는 내지 않는다. 로그에서 캘린더 주소를 지운다. 그래서 DB·백업 파일 자체를 비밀로 다룬다.
- 바깥 공개(Tailscale Funnel)를 전제로 한다: 로그인 잠금, 짐작하기 어려운 관리 화면 주소, 보안 헤더. DB 를 보는 도구는 서버 안에서만 연다.

### 6. 화면만 보고 쓸 수 있게 (HCI)

- 화면마다 지금 할 일 하나만 진한 버튼으로 보인다. 되돌리기는 테두리 버튼, 지우기는 위험 구역.
- 색에 뜻을 하나씩 준다: 회사 보라(주요 동작·현재 위치), 회사 빨강(로고·오류·위험·오늘). 색만으로 구분하지 않고 기호·글자도 붙인다.
- 성공·오류·경고가 한눈에 다르다. 오류 문구는 다음에 할 일을 알려 준다(예: "맞교환을 사용하세요").
- 휴대폰 우선: 숨은 메뉴 없음, 손가락 크기 버튼, 근무표는 하루씩 세로로.
- 그래도 모르면 권한별 1분 사용법 영상과 같은 내용의 글.
- 회사 BI 를 따른다: 로고는 원본 그대로, 다크 모드는 흰색 단색, 지정 서체 Noto Sans KR.

### 7. 테스트로 말한다

- 테스트를 먼저 쓰고 실패를 확인한 뒤 구현한다. 경고도 실패로 본다(`pytest -W error`).
- 화면은 테스트 통과로 끝내지 않고 PC·휴대폰·다크 모드에서 직접 본다.
- 바꿀 때마다 리뷰를 받고, 지적마다 반영하거나 반대 이유를 남긴다.

## 기술 선택

| 선택 | 이유 | 다른 선택지와 비교 |
|---|---|---|
| Django | 로그인·권한·관리 화면·마이그레이션이 다 들어 있다 | FastAPI(예전 노티파이어): 관리 화면·인증을 직접 만들어야 함 |
| SQLite (WAL, IMMEDIATE) | 사용자 수십 명, 서버 한 대. 설치·운영이 없고 백업이 파일 하나. 쓰기가 줄을 서서 동시 수정이 단순 | PostgreSQL·MySQL(운영 부담. 바꾸는 방법은 ARCHITECTURE.md) |
| 서버 렌더링 + htmx | 빌드 없이 팝업·부분 갱신. 화면 코드가 템플릿 하나에 모인다 | React 등 SPA(빌드·API·상태 관리가 생김) |
| Pico.css | 클래스를 거의 안 붙여도 읽기 좋고 다크 모드가 된다 | Bootstrap·Tailwind(클래스가 많아짐) |
| 텔레그램 봇 + 웹 푸시 | 휴대폰으로 바로 받는다. 웹 푸시는 앱 설치 없이 | 문자·메일: 발송 비용·계정 연동이 생김 |
| ICS 구독 | 휴대폰·PC 기본 캘린더가 다 지원. 따로 만들 화면 없음 | 캘린더 API 연동(계정 연결 필요) |
| Tailscale Funnel | 방화벽·인증서 설정 없이 HTTPS 공개 | 사내 리버스 프록시(담당 부서 협의 필요) |
| systemd 유닛 2개 | RHEL 기본. 재시작·부팅 시 시작을 알아서 | Docker(사내 서버에 런타임 추가) |

| 2026-11-11 | 외부 API·시트 가져오기·노티파이어 삭제 | 알림이 앱에 들어와 쓰는 곳이 없어졌다 |
| 2026-11-11 | 설정은 `.env` 하나, 데이터는 `data/` 하나, 작업자 한 프로세스, 유닛 두 개 | 설정·스크립트·타이머·유닛이 여러 곳(유닛 7개)에 흩어져 있었다 |
| 2026-11-11 | 알림 봇 토큰·푸시 키는 `.env` 가 아니라 DB(관리 화면) | 서버에 들어가지 않고 관리자가 바꿀 수 있게 |

| 2026-11-12 | 배포 취소 이전 변경 기록은 다시 배포해도 표시하지 않음(기록 번호로 구분) | 그사이 출근표가 바뀌었을 수 있다. 시계 대신 번호라 시각 보정에 안전 |
| 2026-11-12 | 서버는 개발 PC DB 를 그대로 가져가 시작(예전 DB 변환 명령 삭제) | 옮길 예전 서버가 없다 |
| 2026-11-12 | 사내 서버는 RHEL 9.4+ | Python 3.12·SQLite 3.31+ 필요(RHEL 8 불가) |
| 2026-11-12 | 회사 BI(로고·색·서체)와 HCI 점검 반영 | 처음 쓰는 사람이 묻지 않고 쓰게 |
| 2026-11-12 | 장애 알림은 단톡방(음수 chat_id)으로도 | 관리자 한 명이 아니라 운영 담당 모두가 받게 |

# 캘린더 구독(ICS) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 사용자별 비밀 ICS 구독 주소로 본인 근무를 Google·아이폰·Outlook 캘린더에 자동 연동한다.

**Architecture:** 순수 직렬화 `duty/ics.py` + 서비스 `duty/services/calendar.py`(발급·피드 생성) + 공개 뷰 `/calendar/<token>.ics` + `/alarms/` 화면 영역과 `/help/calendar/`.

**Tech Stack:** Django, SQLite. 새 의존성 없음.

**Spec:** `docs/superpowers/specs/2026-11-11-calendar-design.md` (구속력 있는 기준)

## Global Constraints

- 화면 문구·오류는 한국어. 커밋 `feat:`/`fix:`/`docs:` + 한국어 요약.
- 테스트 먼저(실패 확인) → 구현. `.venv/bin/pytest -W error` 경고 0.
- DB 변경은 `duty/services/`만. "오늘"은 `perms.today()`(`from .. import perms`).
- 실명 금지(테스트는 가상 이름). 토큰 원문·피드 경로를 DB·세션·messages·로그에 남기지 않는다.
- 화면 변경은 브라우저(1400px, 390px)에서 확인. DB 사본·스크린샷은 확인 후 삭제, 서버는 PID로 종료.

### Task 1: ICS 직렬화·발급 서비스·피드 뷰

**Files:**
- Create: `duty/ics.py`, `duty/services/calendar.py`, `duty/migrations/0009_calendarfeed.py`, `tests/test_ics.py`, `tests/test_calendar_feed.py`
- Modify: `duty/models.py`(CalendarFeed), `duty/logging.py` 또는 기존 모듈(경로 치환 로깅 필터), `duty/views/alarms.py` 또는 새 `duty/views/calendar.py`(피드 뷰), `duty/urls.py`, `duty/middleware.py`(피드 경로 통과), `config/settings.py`(`DUTY_SITE_URL` 검증)

**Interfaces (Task 2가 사용):**
- `calendar.issue(user) -> str` — 구독 **주소**(절대 URL) 반환. Member 미연결·`SITE_URL` 없음 → `DutyError`(스펙 문구). 행 생성 또는 해시·`issued_at` 교체(원자적), unique 충돌 시 2회 재시도
- `calendar.revoke(user) -> None` — 행 삭제(없어도 오류 없음)
- 주소 = `settings.SITE_URL.rstrip("/") + reverse("calendar_feed", args=[token])`(Host 헤더 미사용)
- `CalendarFeed.objects.filter(user=...)`로 발급 여부·`issued_at` 표시
- URL 이름: `calendar_feed`(인자 `token`)

**`duty/ics.py` (순수, ORM 없음):**
- `escape_text(s) -> str`: `\\`→`\\\\`, `;`→`\;`, `,`→`\,`, 줄바꿈→`\n`
- `fold(line) -> str`: UTF-8 기준 첫 줄 75옥텟, 이후 줄은 선행 공백 포함 75옥텟 이하, 멀티바이트 문자를 쪼개지 않음, 줄 구분 CRLF
- `Event` dataclass: `uid, dtstamp, start, end, summary, url: str | None` — datetime은 aware여야 하고 UTC로 정규화해 출력(naive면 `ValueError`)
- `calendar(name: str, events: list[Event]) -> bytes`: 스펙의 속성 순서대로, 각 줄 fold 후 CRLF로 연결, 끝도 CRLF, UTF-8

**테스트(먼저):**
- `test_ics.py`: 이스케이프 4종, ASCII 긴 줄 접기(각 줄 ≤75옥텟, 이어 붙이면 원문), 한글 긴 줄 접기(멀티바이트 미분할, 디코드 가능), 빈 캘린더에 VEVENT 없음·METHOD 없음, 이벤트 하나의 필수 속성(UID/DTSTAMP/DTSTART/DTEND Z 형식, TRANSP, STATUS), URL 값 미이스케이프, url None이면 URL·DESCRIPTION 없음, 모든 줄 CRLF
- `test_calendar_feed.py`:
  - issue: 반환 URL이 `SITE_URL`로 시작하고 거기서 추출한 토큰이 43자, DB에는 sha256만(원문 미저장), 재발급 시 이전 토큰 404·새 토큰 200, revoke 후 404
  - 형식 아닌 토큰(42자, 44자, `.`, 비ASCII) 404
  - 로그인 없이 200, 비밀번호 변경 필요 사용자의 토큰도 리다이렉트 없이 200
  - 본인 출근조·관제만 포함, 다른 사람 배정 미포함, 같은 날 출근조+관제 → VEVENT 2개
  - 배포(PUBLISHED) 회차만, 오늘-90일 이전 미포함, 오늘-90일 포함
  - DTSTART/DTEND: 새벽조 06:30 KST → `T213000Z` 전날, 관제 슬롯 시각
  - DTSTAMP = max(published_at, ChangeLog.at) UTC; 배포 후 변경하면 DTSTAMP·ETag 바뀜
  - `published_at` 없는 PUBLISHED 회차 날짜 제외(경고 로그에 회차 id만)
  - 퇴사 Member / User 비활성 / Member 미연결 → 200 빈 캘린더(VEVENT 0), ETag가 이전과 다름
  - 헤더: Content-Type, `Cache-Control: private, no-cache`, `Referrer-Policy: no-referrer`, ETag; `If-None-Match` 일치 → 304(같은 헤더); HEAD 200 본문 없음; POST 405
  - 로그(caplog)에 토큰 원문·경로 없음 — 404(형식 오류·폐기 토큰)·405(POST)에서 `django.request` 레코드의 최종 메시지·args에 토큰·`/calendar/` 경로 없음
  - 로깅 필터 단위 테스트: `django.request` 형식(record.request 포함)과 `django.server` 형식(args에 요청 줄) 레코드 모두, 처리 후 `getMessage()`·args·`record.request`(없애거나 경로 없는 대체물)·`META`에 토큰·`/calendar/` 경로 없음; 5xx 레코드도 치환
  - 서비스: Member 미연결·`SITE_URL` 없음 → `DutyError`; 재발급 시 `issued_at` 갱신
  - Member 이름 변경 후에도 UID(member_pk) 유지·일정 유지
  - `perms.today()`를 하루 옮겨 90일 경계 이벤트가 빠지면 ETag 바뀜
  - 같은 ETag → 304, 일정 변경 후 이전 ETag → 200
  - 304 응답에도 `Referrer-Policy`·`Cache-Control`·`ETag`
  - `ics`: naive datetime → ValueError, KST aware → UTC `Z`로 출력
  - UID 형식 `<YYYYMMDD>-<cell>-<member_pk>@duty-generator`
  - `SITE_URL` 설정 시 URL·DESCRIPTION 포함
- settings 검증: `DUTY_SITE_URL`에 CR/LF, `ftp://`, query, fragment, host 없음 → `ImproperlyConfigured`(검증 함수를 settings에서 분리해 단위 테스트), DEBUG에서 `http://` 허용

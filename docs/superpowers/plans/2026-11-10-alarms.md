> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사람마다 정한 규칙(개인/보고서형, 분·일·영업일 기준, 텔레그램·푸시)으로 웹앱이 직접 당번 알림을 보낸다.

**Architecture:** 순수 계산(`duty/alarms/schedule.py`, `plan.py`, `messages.py`)은 ORM 없이 두고, DB 쓰기는 `duty/services/alarms.py`, 발송 루프는 `manage.py run_alarms`(별도 systemd 프로세스)가 맡는다. 발송 기록을 먼저 쓰고 보낸다(중복보다 누락). 화면은 `/alarms/` 한 페이지 + PWA 서비스 워커.

**Tech Stack:** Django 5.2, SQLite, htmx/Pico(기존), `pywebpush>=2.0` (신규), 텔레그램 Bot API(`urllib`).

**Spec:** `docs/superpowers/specs/2026-11-10-alarms-design.md`

- 화면 문구·오류 메시지는 한국어. 커밋은 `feat:`/`fix:`/`docs:` + 한국어 요약, 끝에 세션 트레일러.

- "오늘"·현재 시각은 `duty.perms.today()` / `django.utils.timezone.localtime()`; 순수 계층은 Asia/Seoul naive `datetime`을 받는다.
- DB 쓰기는 `duty/services/`만. 뷰는 모델을 직접 고치지 않는다.
- 선택값 칸은 `TextChoices` + DB `CheckConstraint`. FK는 `CASCADE`(고아 금지).
- 테스트·커밋·로그에 실명 금지(가상 이름). 발송 실패 로그는 규칙 id·채널·상태 코드만.
- 외부 호출(텔레그램, 푸시)은 테스트에서 절대 실제로 하지 않는다(가짜 sender 주입).
- 신규 의존성은 `pywebpush` 하나뿐.
- 시간 단위는 분. `offset` 범위: before_start 1~10080, days 0~30, bizdays 1~30. `at_minute` 0~1439, before_start면 0.
- 스케줄 키: `dawn, normal, dinner, night, slots`(=`duty.services.prefs.SHIFT_KEYS`), 저장 순서도 이 순서. 유형 순서 `직원, 개발자`, 부서는 코드 오름차순.
- 기본 규칙: ① personal, days, offset 1, at_minute 1080, telegram, shifts [dawn, dinner, night] ② personal, before_start, offset 120, at_minute 0, telegram, shifts [dawn, dinner, night].

```python
from datetime import time

SHIFT_TIMES: dict[str, tuple[str, str]] = {  # duty_notifier config 와 같은 값 (9시=석식교대, 저녁=야간)
    "dawn": ("06:30", "15:30"),
    "normal": ("08:00", "17:00"),
    "dinner": ("09:00", "18:00"),
    "night": ("13:30", "21:30"),
}

def _span(cell: str) -> tuple[str, str]:
    if is_slot_cell(cell):
        a, b = CONTROL_SLOTS[slot_index(cell)][0].split("~")
        return a, b
    return SHIFT_TIMES[cell]

def cell_start(cell: str) -> time:
    return time.fromisoformat(_span(cell)[0])

def cell_end(cell: str) -> time:
    return time.fromisoformat(_span(cell)[1])

def cells_of(keys: list[str]) -> list[str]:
    """스케줄 키(dawn..night, slots) → 칸 키. 빈 목록 = 전부. CELLS 순서."""
    if not keys:
        return list(CELLS)
    return [c for c in CELLS if (is_slot_cell(c) and "slots" in keys) or c in keys]
```

```python
def normalize(kind, shifts, depts, types):
    def pick(vals, order):
        got = [v for v in order if v in set(vals)]
```

```python
"""알림 발송 시각 계산. ORM 없음, Asia/Seoul naive datetime."""
from datetime import date, datetime, time, timedelta

def bizdays_back(d: date, n: int) -> date:
    while n:
        d -= timedelta(days=1)
        if d.weekday() < 5:
            n -= 1
    return d

def send_at(timing: str, offset: int, at_minute: int, day: date, start: datetime) -> datetime:
    if timing == "before_start":
        return start - timedelta(minutes=offset)
    base = day - timedelta(days=offset) if timing == "days" else bizdays_back(day, offset)
    return datetime.combine(base, time(at_minute // 60, at_minute % 60))
```

`info` = 이름 → (부서 코드, 유형). `sent` = (rule_id, date, cell, channel) → 마지막 content_hash.

**규칙**
- 개인: 규칙의 칸(`cells_of(shifts)`)마다 `start = combine(day, cell_start(cell))`, `at = send_at(...)`, `at <= now < start`일 때만.
  - 멤버가 그 칸에 있음: hash = `"in"`. 기록 없음 → 알림. 기록 hash ≠ `"in"`(전에 취소됨) → 다시 알림.
  - 멤버가 그 칸에 없음: 기록이 있고 hash == `"in"`이면 취소 알림, hash = `"out"`. 기록 없으면 아무것도 안 함.
- 보고서형: 하루 1건. 칸 = `cells_of(shifts)`, `start` = 그 칸들 시작의 최솟값, 발송 창 같음. 각 칸 이름을 `info`로 부서·유형 필터. 내용 hash = 표 내용 sha256(앞 16자 이상). 기록 없음 → `[출근표]`, 기록 hash 다름 → `[출근표 변경]`(전체 표 다시).
- 채널마다 별도 `Due`.

**문구 (`messages.py`)** — 요일 `"월화수목금토일"`:
- `day_label(d)` → `"11/16(월)"`; `relative_day(d, today)` → 오늘/내일/day_label.
- 개인: 제목 `당번 알림`, 본문 `"[당번 알림] 11/16(월) 새벽 06:30~15:30\n{이름}님, 내일 새벽 당번입니다."` (장중은 칸 라벨 `"10:30~11:30"` + `"장중당번"`).
- 취소: 제목 `당번 변경`, `"[당번 변경] 11/16(월) 새벽 06:30~15:30\n{이름}님의 근무가 취소되었습니다."`
- 보고: 제목 `출근표`, 첫 줄 `"[출근표] 11/16(월)"` + 조건이 있으면 `" — 매칭엔진실·개발자"`(부서 이름 매핑은 인자로 받음: `dept_names: dict[str,str]`를 `plan`에 키워드 인자로 추가), 이후 칸마다 `"새벽(06:30~) 가, 나"` / 사람이 없으면 `-`. 변경은 첫 줄 `[출근표 변경]`.

### Task 5: `run_alarms` 명령

**Files:** Create `duty/services/alarm_runner.py` (tick), `duty/management/commands/run_alarms.py`; Test `tests/test_run_alarms.py`

**Interfaces:**
- Consumes: `plan`, `RuleSpec`, `Due` (Task 3), senders (Task 4), `published_days` (`duty/services/roster.py`).
- Produces: `tick(now: datetime | None = None) -> int` (보낸 건수). `run_alarms` 옵션 `--once`.

**동작 (`tick`)**
1. `now = timezone.localtime(now or timezone.now()).replace(tzinfo=None)`, `today = now.date()`.
2. `days = published_days(today, today + timedelta(days=45))`.
3. 규칙: `enabled=True`, `user__is_active=True`, `select_related("user__member")` → `RuleSpec` (personal의 member_name = 연결된 멤버 이름, 비활성 멤버면 None). `info`, `dept_names`는 Member/Department에서.
4. `sent` = 그 규칙들의 `AlarmSent`(date ≥ today).
5. `plan(...)`의 각 Due에 대해 채널 가능 여부 확인: telegram은 `telegram_enabled()` 그리고 chat_id 있음, push는 `push_enabled()` 그리고 구독 ≥1. 불가면 건너뜀(기록하지 않음).
6. 가능하면 `transaction.atomic()`으로 `AlarmSent.update_or_create(rule, date, cell, channel, defaults={content_hash, sent_at})` **먼저** 쓰고, 그다음 발송. 예외는 잡아서 `logger.warning("alarm send failed rule=%s channel=%s err=%s", rule_id, channel, type(e).__name__)` (본문·이름 금지). push는 구독마다 보내고 `Gone`이면 그 구독 삭제.
7. 명령: `--once`면 `tick()` 한 번. 아니면 무한 루프: `tick()` 후 다음 분 0초까지 `time.sleep`. 예외로 루프가 죽지 않게 `logger.exception` 후 계속.

- [ ] **Step 1: 실패 테스트** (senders monkeypatch로 호출 목록 수집; `fixed_today`와 `now` 인자 사용; 배포 회차·Commute를 만드는 기존 테스트 헬퍼/fixture 재사용 — `tests/test_views_roster.py` 등에서 published 데이터 만드는 방식 확인)
  - 기본 규칙 사용자 + chat_id + 월 새벽 근무: 일 18:00 tick → 텔레그램 1건, AlarmSent 1행. 같은 시각 다시 tick → 0건.
  - chat_id 없으면 0건·기록 없음. 토큰 없으면 0건.
  - push 규칙 + 구독 2개 → 2번 호출, 하나가 Gone → 그 구독 삭제, 기록은 1행.
  - 발송기 예외 → 기록은 남고(누락 쪽 실패) tick은 계속, 로그에 이름 없음(`caplog`).
  - 비활성 사용자·꺼진 규칙 → 0건.

# 근무표 통합(입력 방식 갈래 제거·근무표 설정 화면·여러 근무표 한 화면) 설계

- 상태: 사용자 승인(1ad9e5c, §15 기본안 셋 포함) 뒤 2차 리뷰(다관점 44건 + 독립 리뷰)와 Codex 리뷰(d8cf021) 반영본.
- 화면 문구: 1·2단계 화면 글(⚠ 줄, 생성 확인창, 끈 단계 안내, 2단계 공지)의 최종 문구는 구현 계획 `docs/superpowers/plans/2026-11-17-boards-unify-1-2.md`(4660174, 리뷰 반영)를 따른다. 이 문서의 해당 예문은 뜻을 보이는 초안이다.
- 목표: IT 당번표와 시장운영실을 **같은 코드 한 길**로 돌린다. 근무표마다 다른 점은 코드 갈래(`Board.input_mode`)가 아니라 **근무표 설정 값(데이터)**으로 둔다. 근무표 관리자가 슈퍼유저·관리 화면을 거치지 않고 앱 안의 [근무표 설정] 한 화면에서 운영한다. 근무표 화면은 근무표 N개를 한 번에 볼 수 있게 한다.
- 출발점: `main` 02c79c5(PR #41). **운영 서버가 이 버전으로 돌고 있다**(근무표 일반화 1~4단계 + `add_board` 배포·마이그레이션 완료). 시장운영실 근무표(`input_mode=direct`)가 이미 만들어져 실제로 쓰이고 있을 수 있다. 업그레이드 설계(10절)는 이 상태의 실데이터를 전제로 한다.
- 구현이 끝나면 이 문서의 내용은 `docs/ARCHITECTURE.md`·`OVERVIEW.md`·`OPERATIONS.md`·`PRINCIPLES.md`에 합치고 이 파일은 지운다(5단계 PR).

## 1. 배경

- 사용자 지적(2026-11-17): "IT/시장운영 두 부서의 기능들을 각각 따로 가져가는 게 아니라 한 번에 품을 수 있게 일반화해야 유지보수도 편하고 다른 부서가 추가됐을 때 좋다. 전반적으로 아예 따로 구현된 느낌이 있다", "관리자의 운영 공수가 너무 들면 안 된다".
- 지금 `Board.input_mode`(collect | direct)가 12개 파일 51곳에서 동작을 가른다(`git grep -n -E "InputMode|input_mode|\bdirect\b" -- duty`, 마이그레이션·영상 파일 포함). 갈래마다 테스트·문구·도움말이 따로 있다(`test_direct_periods.py`, `test_views_direct.py`, `help.STEPS["direct"]`).
- 운영 작업이 네 곳(Django 관리 화면·앱 화면·`add_board` 명령·[그룹] 메뉴)에, 권한 개념이 넷(슈퍼유저, 근무표 관리 그룹, 부서 입력 그룹, 그룹 관리자 `GroupKeeper`)으로 흩어져 있다. 근무표 관리자가 사람 하나를 더하려면 슈퍼유저에게 부탁해야 한다.
- 근무표 화면은 근무표 하나씩만 본다(`.seg` 버튼). 근무표가 늘수록 버튼이 늘고, 두 근무표를 같이 보는 방법이 없다.
- 보는 사람은 60세 가까운 부장들이다(변화를 싫어함, 시력이 좋지 않음). 관리자 1~2명이 다른 업무와 함께 돌린다.

## 2. 목표와 범위 밖

목표

1. `input_mode`와 그 갈래를 없앤다. 회차 단계·누가 입력하는지·채우기 버튼·빈 평일 처리가 모두 데이터와 한 규칙으로 정해진다.
2. 근무표 관리자가 [근무표 설정] 한 화면에서 관리자·사람(계정 발급 포함)·근무 정의·부서 출근조·점심 시각·부서 입력 담당자·단계를 고친다.
3. 권한을 셋(근무표 관리자, 부서 입력 담당자, 슈퍼유저)으로 줄인다. 그룹 관리자와 [그룹] 화면을 없앤다.
4. 근무표 화면에서 여러 근무표를 골라 한 표에 겹쳐 본다. 근무표 하나든 여럿이든 같은 코드 한 길이다.
5. **업그레이드한 날 IT·시장운영실 모두 보이는 동작이 그대로다**(1단계, 스냅샷 테스트로 지킨다). 사용자가 정한 공통 규칙(IT 빈 평일 경고만 등)은 따로 2단계로 켠다.

범위 밖

- 근무표 만들기는 여전히 슈퍼유저(관리 화면 "근무표 추가" 또는 `manage.py add_board`). 휴장일·알림 설정·로그인 잠금 해제·부서 만들기도 슈퍼유저(관리 화면)에 남는다.
- **인사이동(사람의 부서·근무표 옮기기)은 슈퍼유저가 관리 화면 사용자 → 부서에서 한다**(`accounts.on_department_change` 가 개인 알림 발송 기록을 정리한다). 이름이 전체에서 고유해서 옮길 사람을 새로 추가하는 우회는 막힌다. 지원 근무(다른 근무표에 하루 들어가기)는 지원하지 않는다(날 메모로 적는다).
- 사람 지우기(퇴사 = 재직 끄기만), 근무조 5개 이상(키 늘리기), 근무표 지우기, code 바꾸기.
- 사용법 영상 다시 찍기(영상은 IT 화면 그대로 맞다. 글 도움말만 고친다).
- 통계의 근무표 고르기: 관제를 쓰는 근무표가 IT 하나뿐이라 지금 그대로 둔다(`ponytail:` 주석 "관제 있는 근무표가 둘째로 생기면 select").

**남는 IT 가정**(이 설계 뒤에도 코드에 남는 것, 알고 둔다)

| 자리 | 가정 | 처리 |
|---|---|---|
| `services/alarms.py:29`·`alarms/forms.py:53,55,71` | 부서 없는 계정의 기본 근무표 = `boards.it_board()` | 5단계: `boards.home(user)` 로 바꾼다(부서 없는 시장운영실 관리자가 IT 로 잡히지 않게) |
| `boards.it_board()` | code `it` 로 IT 를 찾는다 | 위 대체 뒤 마이그레이션·테스트에서만 쓴다. 남은 호출은 5단계에서 다시 grep 해 적는다 |
| 생성 방식 상자 글 | IT 관제 10칸 문장이 템플릿에 박혀 있다 | 1단계: 관제 정의에서 만든다(6.1) |
| 사용법 영상 | IT 화면으로 찍었다 | 그대로(글 도움말이 근무표마다 단계 이름을 보인다) |

## 4. 용어

| 용어 | 뜻 |
|---|---|
| 단계 | 회차 상태(`Period.status`) 다섯 값. 근무표마다 화면 이름이 다르고, 작성 중·마감은 끌 수 있다 |
| 켠 단계 | 그 근무표가 쓰는 단계: (작성 중) → 취합 중 → (마감) → 생성됨 → 배포됨 |
| 근무표 관리자 | 그 근무표 관리 그룹(`Board.admin_group`) 멤버 |
| 관리자 계정 | 어느 근무표든 관리 그룹 멤버인 계정 |
| 부서 입력 담당자 | 그 부서 입력 그룹(`Department.input_group`) 멤버. 화면 이름은 "입력 담당자" |
| 내 근무표 | `boards.home(user)`(내 부서의 근무표 → 내가 관리하는 첫 근무표 → 첫 근무표) |
| 고른 근무표 | 근무표 화면에서 겹쳐 볼 근무표 목록 |
| 바꿀 수 있는 근무표 | `perms.can_edit` 가 참인 근무표: 그 근무표 부서 사람(오늘 이후)이거나 그 근무표 관리자 |
| 구역 | 겹친 화면의 날짜 칸 안에서 근무표 하나가 차지하는 부분 |

## 5. 데이터 모델과 단계 규칙

정해진 값 칸은 `choices` + DB `CheckConstraint`, 기록을 남길 FK는 `PROTECT`(CLAUDE.md).

### 5.1 Board

| 칸 | 내용 |
|---|---|
| ~~input_mode~~ | 지운다(제약 `board_input_mode_valid` 와 함께) |
| use_draft | bool, 기본 참. "작성 중 단계 사용" |
| use_close | bool, 기본 참. "마감 단계 사용" |
| step_draft, step_collecting, step_closed, step_generated, step_published | 단계 화면 이름. CharField(16), 기본값 = 지금 `PeriodStatus` 이름(작성 중·취합 중·마감·생성됨·배포됨). DB 제약: 빈 글자 금지(`board_step_names_set`). 폼: 줄바꿈 금지, 다섯 이름이 서로 달라야 함 |

- 끈 단계도 이름을 가진다: 단계를 끈 뒤에도 그 상태에 남은 회차·상태 기록이 이름으로 보여야 한다(지금 `step_label` 이 직접 입력 근무표의 작성 중·마감을 `PeriodStatus` 이름으로 보이는 것과 같다).
- 단계를 켜고 끄는 것은 막지 않는다(진행 중 회차가 있어도). 끈 단계에 남은 회차는 "다른 상태로 옮기기"로 켠 단계로 옮긴다(5.2 의 `move_targets` 가 그대로 처리한다). 그런 회차가 있으면 저장 결과와 회차 화면이 알려 준다(7.2 단계 칸, 6.1).
- 1·2단계에서는 관리 화면이 저장된 근무표의 단계 칸을 읽기 전용으로 둔다(만들 때만 고친다). 임시 기준(`legacy_admin_entry = not use_close`)이 2단계까지 입력 그룹 자동 생성(`Department.save`)·부서 폼 검사를 정하므로, 그동안 단계를 바꾸면 그 기준과 섞인 중간 상태가 생긴다. **3단계에서 기준 함수를 지우는 것과 함께** 관리 화면·[근무표 설정] 단계 칸 편집을 연다.

### 5.2 단계 규칙(모델 메서드, 쿼리 없음)

`Board` 에 순수 메서드를 둔다(DB 를 읽지 않아 어디서 불러도 싸다). 지금 `models.step_label(board, status)`·`DIRECT_STEPS` 를 대신한다.

```python
def step_name(self, status) -> str          # 화면 이름(끈 단계도)
def steps(self) -> list[str]                # 켠 단계, 순서대로: [draft?] collecting [closed?] generated published
def first_step(self) -> str                 # draft if use_draft else collecting
def generate_from(self) -> str              # closed if use_close else collecting
def editable(self) -> set[str]              # {draft} | ({collecting} if not use_draft else set())
def move_targets(self, status) -> list[str] # [s for s in MOVABLE if s in steps() and s != status], 배포됨이면 []
```

| 규칙 | IT(둘 다 켬) | 시장운영실(둘 다 끔) | 지금 코드와 같은가 |
|---|---|---|---|
| 새 회차 상태 | 작성 중 | 취합 중(입력 중) | 같다(`save_draft` 의 `new and direct`) |
| 기간 수정 | 작성 중 | 작성 중·취합 중 | 같다(`editable`) |
| 생성(확정) 가능 | 마감·생성됨 | 취합 중·생성됨 | 같다(`run_generation` 첫 검사) |
| 옮기기 대상 | 작성 중·취합 중·마감 중 지금 것 빼고 | 취합 중만(지금이 취합 중이면 없음) | 같다(`move` 와 `_movable`) |
| 끈 단계에 남은 회차 | — | 작성 중·마감 회차 → 취합 중으로만 | 같다 |
| 출근표 입력 | 취합 중 | 취합 중 | 같다 |
| 배포 | 생성됨 | 생성됨 | 같다 |

다른 조합(작성 중만 켬, 마감만 켬)도 같은 메서드로 정해진다. 예: 마감만 끄면 작성 중 → 취합 중 → 생성됨.

### 5.3 Department

- 1단계: `clean` 의 "직접 입력 근무표는 부서 하나" 검사를 지운다. `save` 의 그룹 자동 생성은 지금 그대로 두고 조건만 `input_mode == COLLECT` → `not legacy_admin_entry(board)` 로 바꾼다(같은 결과). 관리 화면 `DepartmentForm` 의 "직접 입력 근무표 부서는 입력 담당자 없음" 검사도 같은 기준으로 그대로. 입력 그룹 자동 생성에 기대는 지금 테스트(`input_group.user_set` 19곳)가 1단계에서 그대로 통과해야 한다.
- 3단계: `save` 는 입력 그룹을 만들지 않는다(이름을 바꿀 때 그룹 이름을 따라 바꾸는 것만 남긴다). 그룹은 **첫 입력 담당자를 넣을 때** `Department.ensure_input_group()` 이 만든다("<부서> 출근표 입력". 부르는 곳은 `board_settings.add_assignee` 와 관리 화면 부서 폼의 담당자 저장). 같은 이름의 그룹이 이미 있으면 한국어 오류("같은 이름의 그룹이 이미 있습니다: …. 슈퍼유저에게 그 그룹 이름을 바꿔 달라고 하세요.")로 막는다. 그룹이 없는 부서와 빈 그룹인 부서는 `perms.managed_departments` 에서 똑같이 "관리자만 입력"이라, 미리 빈 그룹을 만들 까닭이 없다. 기존 IT 부서 그룹은 그대로 둔다. 관리 화면 부서 폼의 담당자 금지 검사를 지우고, 이름 겹침은 칸 오류로. `legacy_admin_entry` 는 이 두 자리와 함께 3단계에서 지운다.

### 5.4 버튼 이름(순수 함수)

단계 이름에서 버튼 글자를 만든다. IT·시장운영실 기본 이름에서 지금 글자가 그대로 나온다.

| 버튼 | 규칙 | IT | 시장운영실 |
|---|---|---|---|
| 취합 열기(작성 중 → 취합 중) | `step_collecting` 끝의 " 중"을 뗀 말 + " 열기" | 취합 열기 | (작성 중을 안 써서 없음) |
| 마감(취합 중 → 마감) | 같은 말 + " " + `step_closed` | 취합 마감 | (없음) |
| 생성 | 켜진 장중관제 정의가 있으면 "장중관제 생성", 없으면 `step_generated` 끝의 "됨"을 뗀 말 | 장중관제 생성 | 확정 |
| 다시 생성(생성됨) | 장중관제가 있을 때만 "재생성"(무작위라 다시 돌릴 뜻이 있다) | 재생성 | (없음) |
| 생성 취소(생성됨에서 옮길 곳이 하나뿐일 때) | 생성 버튼 말 + " 취소", 그 한 곳으로 | (옮길 곳이 셋이라 "다른 상태로 옮기기") | 확정 취소 |

- 생성됨에서 옮길 곳이 둘 이상이면 지금처럼 "다른 상태로 옮기기" 상자, 하나면 [… 취소] 버튼. 생성됨이 아닌 상태의 옮기기는 늘 상자.
- **생성됨에서 나가는 확인창은 하나**(2단계): [… 취소] 버튼과 "다른 상태로 옮기기" 상자가 같은 템플릿 변수 `leave_generated_confirm` 을 쓴다. 글은 **그 회차에 실제로 있는 배정**(`DutyAssignment` 의 관제 칸·점심당번 유무, 지금 켜진 정의가 아니라)으로 만든다: 둘 다 있으면 "생성 결과(장중관제·점심당번 배정)가 지워지고 출근표는 그대로 남습니다. 계속할까요?", 하나만 있으면 그것만, 없으면 "출근표는 그대로 남습니다. 계속할까요?". 정의를 끈 뒤에도 남은 관제 배정이 지워진다는 것을 숨기지 않게. 1단계는 지금 두 글(직접 입력 [확정 취소] 글, IT 옮기기 상자 글)을 그대로 둔다(6.1 문구 규칙).
- 상태를 말하는 글은 조사를 붙여 만든다: "'<이름>' 상태로", "'<이름>'(으)로".
- **떼기를 할 수 없는 이름**(취합 열기·마감은 `step_collecting` 이 " 중"으로 끝나지 않을 때, 생성은 관제가 없고 `step_generated` 가 "됨"으로 끝나지 않을 때)은 이름 전체를 쓰는 꼴로 만든다: "'<취합 중 이름>'(으)로", "'<마감 이름>'(으)로", "'<생성됨 이름>'(으)로", 취소는 "'<돌아갈 단계 이름>'(으)로 돌아가기". 예: 이름을 "확정"으로 두면 생성 버튼은 [확정](떼기 없이 그대로), "완료됨"이면 [완료], "작성"이면 ['작성'(으)로]. 기본 이름은 모두 떼기가 되므로 지금 글자 그대로다.
- 단계 폼은 **켠 단계에서 나오는 버튼 글자가 비거나("중"·"됨"만 적음) 서로 겹치면** 그 이름 칸 오류로 막는다("버튼 이름이 비거나 다른 버튼과 같아집니다: […]"). 관리 화면 근무표 폼도 같은 검사(같은 함수). 미리보기는 이 함수가 만든 실제 글자를 보인다.

### 5.5 RosterPref

### 5.6 GroupKeeper

- 3단계에서 모델·관리 화면 인라인을 지우고 `DeleteModel` 마이그레이션을 둔다. 행은 권한 지정일 뿐 기록(변경·상태)이 걸려 있지 않아 남길 까닭이 없다(원칙 2 "쓰지 않게 된 기능은 지운다"). 그룹 관리자가 하던 멤버 넣고 빼기는 [근무표 설정]의 관리자·입력 담당자 칸이 대신한다.
- 운영 서버에 행이 있으면 업그레이드 전에 목록을 적어 둔다(10.3 확인 명령). 그룹 관리자였지만 근무표 관리자가 아닌 사람이 계속 멤버를 고쳐야 하면, 업그레이드 뒤 근무표 관리자가 그 사람을 관리자로 넣을지 정한다(자동으로 넣지 않는다: 관리자는 회차·배포까지 할 수 있어 권한이 넓어진다).

### 5.7 계정(`accounts.py`)

- `issue_account(user, revoke_links=True)`: 인자를 더한다. 관리 화면 액션(슈퍼유저, 탈취 의심)은 지금처럼 끊고(`True`), [근무표 설정]의 초기화는 `revoke_links=False`("비밀번호를 잊었어요" 길: 캘린더 구독·텔레그램·푸시를 남긴다). 비밀번호가 바뀌면 Django 가 다른 기기의 로그인을 끊고, 로그인 잠금은 지금처럼 푼다(`reset`).
- 첫 발급 판단: 지금 "쓸 수 있는 비밀번호가 없음"은 퇴사 뒤 다시 재직한 사람도 참이라 기본 알림 규칙이 두 번 생긴다. `first = not user.has_usable_password() and user.last_login is None` 로 바꾼다.
- 임시 비밀번호: 헷갈리는 글자(0·o·1·l·i)를 뺀 `23456789abcdefghjkmnpqrstuvwxyz` 에서 `secrets.choice` 로 10자, 띄어쓰기 없음. 관리 화면 액션도 같은 함수라 같이 바뀐다.
- `deactivate(user)`(새 함수): 재직 끄기 + 쓸 수 없는 비밀번호(모든 로그인이 끊긴다) + `calendar.revoke` + `alarms.clear_telegram` + `alarms.delete_all_subscriptions`. 다시 재직은 재직만 켜고, 로그인하려면 [계정 발급]을 다시 한다(계정 열이 "발급 전"으로 보인다).

### 6.2 새 서비스 `services/board_settings.py`(3·4단계)

공통 규칙

- 모든 함수의 첫 줄은 `_require_admin(by, board)`(그 근무표 관리자가 아니면 `PermissionDenied`). 트랜잭션 안에서 근무표와 대상을 다시 읽는다.
- **근무표 범위 검사(IDOR)**: POST 로 온 부서·사람·근무 정의 id 는 서비스가 board 범위로 다시 확인한다 — `dept.board_id == board.id`, `user.department.board_id == board.id`(관리자 넣기는 아래 후보 규칙), 근무 정의 formset 의 `instance=board`, 부서 줄 폼은 그 근무표 부서만. 범위 밖이면 `PermissionDenied`(뷰는 404). 부서 함수도 `board` 를 인자로 받아 `_require_admin(by, board)` 와 `dept.board_id == board.id` 를 함께 본다.
- **기록**: 모든 쓰기 함수 끝에 같은 꼴 로그 한 줄 `"board %s: %s %s by %s"`(근무표 code, 동작, 대상 아이디 또는 부서 코드, 누가 아이디)와 Django `LogEntry` 한 줄(`user`=누가, 대상 객체 = 사람·부서·근무표, `object_repr` = 아이디·부서 코드·근무표 code, `change_message` = 한국어 동작 이름 예 "근무표 ops: 관리자 넣기"). **실명·비밀번호는 둘 다 넣지 않는다.** Django 5.2 의 `log_actions` 는 `object_repr` 에 `str(obj)`(= 실명)을 넣으므로 쓰지 않고 `LogEntry.objects.create(...)` 를 감싼 작은 함수 `_audit(by, obj, repr, msg)` 를 쓴다. 웹 로그는 기본 14일만 남지만 `LogEntry` 는 DB 에 남는다.

## 7. [근무표 설정] 화면(3·4단계)

### 7.1 들어가기

- 주소 `/settings/?board=<code>`. 메뉴 [근무표 설정]은 어느 근무표든 관리자에게 보인다(`perms.is_admin`).
- 제목은 늘 "근무표 설정 · <근무표 이름>". 관리하는 근무표가 둘 이상이면 제목 아래 근무표마다 링크(`.seg`, 지금 근무표는 채운 모양) — select 를 바꾸고 [열기]를 잊은 채 다른 근무표를 고치는 일이 없게.
- 그 근무표 관리자가 아니면 404(`_period` 와 같은 방식). 슈퍼유저라도 관리 그룹에 없으면 못 들어온다(지금 원칙 그대로).
- 제목 아래 칸 바로가기 줄: [사람] [관리자] [입력 담당자] [근무 정의와 부서] [회차 단계] (`#people`·`#admins`·`#assignees`·`#shifts`·`#steps`). 폼마다 action 과 성공 redirect 주소에 그 칸의 앵커를 붙여 저장 뒤 같은 칸으로 돌아온다. 결과 메시지는 `messages` 의 `extra_tags` 에 칸 이름을 넣어 그 칸 제목 바로 아래에 그리고, 맨 위의 공통 메시지 자리에는 칸 태그가 없는 것만 그린다.

### 7.2 칸(위에서 아래로)

화면 하나에 칸(`<section id=…>`)을 쌓고 칸마다 따로 저장한다(한 칸의 오류가 다른 칸의 입력을 날리지 않게). 칸 제목 옆에 한 줄 설명.

1. **사람**(`#people`, 4단계)
   - 표는 읽기 글자: 이름, 아이디, 부서, 구분(켜진 장중관제 정의가 있는 근무표만), 계정(**발급 전 / 첫 로그인 대기 / 사용 중** — 쓸 수 있는 비밀번호 유무와 `must_change_password` 로), 동작. 맨 앞에 선택 체크박스(발급할 사람 고르기).
   - 줄마다 `<details><summary>고치기</summary>`: 펼치면 그 줄 폼 하나(이름·구분 입력칸과 [저장], `set_person`) — 여러 줄을 늘 입력칸으로 두면 한 줄만 저장할 때 다른 줄에서 고친 것이 알림 없이 사라지므로, 펼친 줄만 고치게 한다. 그 아래 `section.danger` 안에 `button.danger-btn` 둘: [비밀번호 초기화](확인창 "○○(ops07)의 비밀번호를 새로 만들까요? 로그인 중인 기기에서 로그아웃되고 로그인 잠금도 풀립니다. 캘린더·텔레그램·푸시 연결은 그대로입니다."), [퇴사](확인창 "○○(ops07)을(를) 퇴사 처리할까요? 로그인할 수 없고 캘린더·텔레그램·푸시 연결이 모두 끊깁니다."). 오늘 이후 칸이 있으면(배포된 근무와 배포 전 회차의 출근표·당번 모두) 저장하지 않고 그 줄 아래에 목록("12/3 정상 — 12월 회차(배포됨)", "1/5 근무조 2 — 1월 회차(입력 중)" 처럼 날짜·칸·회차 이름·단계 이름)과 "이 근무 N칸은 그대로 남습니다. 근무표·입력 표에서 다른 사람으로 바꾸세요."를 보이고 [그래도 퇴사 처리]를 한 번 더 누르게 한다(본 칸 수를 함께 보낸다).
   - 퇴사 뒤 메시지: "○○을(를) 퇴사 처리했습니다. [다시 재직]으로 되돌릴 수 있습니다." + 남은 칸이 있으면 같은 목록(배포된 날은 하루 화면 링크, 배포 전 회차는 그 회차의 입력 표 링크).
   - 읽기 줄의 동작: 발급 전이면 [계정 발급]. 관리자 계정 줄은 체크박스·[고치기]·동작이 없고 "관리자 계정은 슈퍼유저에게"를 보인다.
   - 표 아래 [선택한 사람 계정 발급](한 번에 여럿, `issue`). [계정 발급]·[비밀번호 초기화]·[선택한 사람 계정 발급]은 누르면 바로 꺼진다(`onsubmit` 에서 `disabled`).
   - **임시 비밀번호 결과 상자**: 발급·초기화 POST 는 redirect 하지 않고 설정 화면을 그 자리에서 다시 그려(`#people`) 사람 칸 제목 아래에 결과 상자를 둔다. 사람마다 "○○(ops07)" 옆에 비밀번호를 고정폭 큰 글씨(`<code>`, 1.4rem 이상)로, 위에 굵게 "띄어쓰기 없이 입력합니다. 사람마다 1:1로만 전달하세요. 이 상자를 닫거나 다른 버튼을 누르면 다시 볼 수 없습니다. 적은 뒤에 다음 사람을 발급하세요(여럿이면 체크해서 한 번에)." 상자는 [닫기](설정 화면 GET 링크)나 다음 동작 때까지 남는다. 비밀번호는 응답 본문에만 있고 세션·메시지·DB·로그에 남지 않는다(지금 관리 화면 액션은 메시지(세션)로 보내지만 설정 화면은 그렇게 하지 않는다). 새로고침하면 브라우저가 다시 보낼지 묻고, 다시 보내면 새 비밀번호가 나간다(앞 비밀번호는 무효) — 상자 글에 "새로고침하지 마세요"를 넣는다.
   - 퇴사자는 표 아래 접힌 목록(`<details>`)에 [다시 재직]과 함께. 다시 재직한 사람은 계정 열이 "발급 전"이라 [계정 발급]으로 다시 준다.
   - 표 아래 "사람 추가" 폼: 이름·아이디·부서(부서가 하나면 숨김)·구분(켜진 장중관제 정의가 있는 근무표만). 아이디 칸은 다음 빈 번호(`<code><nn>`, `add_board` 와 같은 꼴)를 미리 넣어 두고 고칠 수 있다. 칸 밑에 "아이디에는 실명을 쓰지 않습니다(영문 소문자·숫자·_)". 폼 아래 한 줄: "부서·근무표를 옮기는 인사이동은 슈퍼유저에게 부탁하세요."
   - 모바일(390px): 표 줄이 카드처럼 세로로 접힌다(이름·아이디 한 줄, 나머지 한 줄씩).
2. **관리자**(`#admins`, 3단계): 지금 관리자 목록(퇴사자는 "(퇴사)"). [빼기]는 나 자신과 퇴사한 관리자 줄에만, 다른 재직 관리자 줄은 "빼기는 슈퍼유저에게". 재직 중인 관리자가 나 하나면 내 줄도 [빼기] 대신 "마지막 관리자". 아래 넣기: select(후보 = 재직 중인 그 근무표 사람 + 부서 없는 계정, 이름 가나다 순, 이미 관리자인 사람은 뺌, "이름(부서)") + [넣기].
3. **부서 입력 담당자**(`#assignees`, 3단계): 부서마다 담당자 목록([빼기]). 비어 있으면 그 자리에 "담당자 없음 — 근무표 관리자만 입력합니다". 넣기 select 는 그 근무표 재직자, 이름 가나다 순, 이미 든 사람은 뺀다. 부서가 하나뿐인 근무표도 같은 모양.
4. **근무 정의와 부서**(`#shifts`, 3단계)
   - 근무 정의: 관리 화면 인라인과 같은 칸(키(중립 이름, 저장한 줄은 잠김)·이름·시작·끝·자격 근무조·자격 구분·기본 알림·사용) + 빈 추가 줄 하나. 지우기 칸 없음. 줄마다 `fieldset` 카드를 CSS grid 로 늘어놓는다(1400px 에서 한 줄에 여럿, 390px·아주 크게에서 한 줄에 하나) — 표 하나로 두면 8칸이 390px 에서 넘친다.
   - 부서: **부서마다 `fieldset` 하나** — 근무조 체크박스 목록(이름 + 시각, 시작 시각 순, 그 부서 "가능한 출근조") + 점심 시작·끝. 행렬 표로 두면 열 머리가 밀려 엉뚱한 칸에 체크하게 되므로 부서별 덩어리로 둔다(폭과 상관없이 같은 마크업).
   - 근무 정의와 부서를 [저장] 하나로 함께 저장한다(`save_shifts`). 같은 저장에서 되는 것: 근무조 이름·시각 고치기, 끄기, 부서 출근조 옮기기·빼기, 점심 시각. **새 근무조를 더하면 저장한 뒤에야 부서 덩어리에 그 체크박스가 생기므로, 체크하고 한 번 더 저장한다**(JS 없는 폼이라서. 칸 위에 그렇게 적는다).
   - 저장한 뒤 켜진 근무조 가운데 **어느 부서에도 체크되지 않은 것**이 있으면, `#shifts` 로 돌아와 부서 덩어리 바로 위에 눈에 띄는 경고 상자 "⚠ 아직 부서에 배정되지 않은 근무조: ○○. 아래 부서에서 체크하고 [부서 저장]을 누르세요. 체크하지 않으면 입력 표에 칸이 생기지 않습니다."와, 부서 덩어리 아래 큰 주 버튼 [부서 저장](같은 `save_shifts` 폼의 저장 버튼을 그 자리에 하나 더)을 둔다. 배정되지 않은 근무조가 없으면 경고도 둘째 버튼도 없다.
   - 위에 관리 화면과 같은 경고(이름·시각을 바꾸면 발송 창이 열린 알림이 한 번 다시 나가고 옛 CSV 열 이름이 맞지 않는다, 저장한 줄은 '사용'을 끈다).
5. **회차 단계**(`#steps`, 3단계): 맨 아래, `<details>`로 접어 둔다(제목 "회차 단계 — 근무표를 처음 만들 때 정하는 값"). 체크 "작성 중 단계 사용"·"마감 단계 사용", 다섯 이름 칸. 끈 단계 칸은 흐리게 하지 않고 옆에 "(쓰지 않음 · 남은 회차·기록 표시용)". 미리보기(서버가 다시 그릴 때, JS 없음): "저장된 단계: 입력 중 → 확정 → 배포됨", "버튼: [확정] [확정 취소] [배포…]"처럼 **실제 버튼 글자**(5.4)로. [저장]에 확인창 "진행 중인 회차의 단계 이름과 버튼이 바로 바뀝니다. 계속할까요?". 저장 뒤 끈 단계에 회차가 남았으면 성공 대신 경고(6.2 `save_steps`).

### 7.3 검사(관리 화면 규칙 재사용)

- 근무 정의: `BoardShiftForm`·`BoardShiftFormSet` 그대로(시각, 이름, 켜진 근무조 하나 이상, 시작 시각 서로 다름, 관제 자격, 키 잠금, 지우기 없음). "부서마다 켜진 입력 근무조 하나 이상"은 같은 저장의 부서 덩어리 값으로 본다(6.2).
- 부서: 출근조는 그 근무표의 근무조 정의만, 하나 이상. 점심 시각은 둘 다 비우거나 둘 다 넣고 시작 < 끝(`department_lunch_valid` 와 같은 문구).
- 사람: `validate_member_name`, 이름 전체 고유, 아이디 모양·대소문자 겹침(6.2), `user_type_matches_department` 제약.
- 단계: 이름 비지 않음·줄바꿈 금지·서로 다름.
- 오류는 칸 옆에 한국어로(`form.labeled`, placeholder 대신 label).

### 7.4 Django 관리 화면에 남는 것

- 근무표: 추가(code·이름·단계 칸 + 근무 정의 인라인), 편집(1·2단계는 단계 칸 읽기 전용, 3단계부터 편집). "그룹 관리자는 이 링크에서" 문구를 "관리자·입력 담당자는 앱의 [근무표 설정]에서"로(3단계).
- 그룹: `GroupKeeperInline` 을 빼고 이름·멤버 보기만 남긴다(멤버는 사용자 편집 폼의 "그룹" 칸이나 [근무표 설정]에서 고친다).
- 사용자·부서·휴장일·알림 설정·계정 발급 액션·로그인 잠금: 그대로(슈퍼유저 비상용·드문 일. 관리자 계정의 발급·퇴사, 재직 관리자 빼기, 인사이동은 여기서).
- **재직 관리자 한 명 이상 규칙은 관리 화면에서도 같다**(3단계): 사용자 편집 폼("그룹" 칸에서 관리 그룹을 빼거나 "재직"을 끔)과 사용자 목록의 일괄 동작(지금은 재직을 끄는 일괄 동작이 없다 — 기본 "선택한 사용자 삭제"는 기록 FK `PROTECT` 로 대부분 막히지만 관리 그룹 멤버 삭제도 같은 검사를 거치게 `delete_queryset`·`delete_model` 에 건다. 재직 끄기 일괄 동작을 나중에 더하면 그것도)이 `board_settings._keep_active_admin` 과 같은 공통 검사(`boards.active_admin_left(board, removing=user)` 같은 순수 판단 + 저장 전 검사)를 거친다. 어기면 저장하지 않고 한국어 오류 "○○ 근무표에 재직 중인 관리자가 남지 않습니다. 먼저 다른 관리자를 넣으세요."(폼은 칸 오류, 일괄 동작은 오류 메시지로 아무것도 바꾸지 않음). 관리 그룹 자체의 멤버를 고치는 길(관리 화면 "그룹")은 보기만 남기므로(위) 따로 막을 곳이 없다.
- [근무표 설정]에서 한 일의 기록: 대상 사람·부서·근무표의 관리 화면 편집 페이지 오른쪽 위 [기록]에 `LogEntry` 로 보인다. (관리 화면 첫 화면의 "최근 작업"은 **로그인한 슈퍼유저 자신의 작업만** 보이므로 거기서는 보이지 않는다 — OPERATIONS 에 적는다.)

|---|---|

| 근무표 관리자 | 그 근무표의 회차·생성·배포·메모·통계·이력·지난 날짜 수정, 모든 부서 출근표, **[근무표 설정]**(사람(관리자 계정 제외)·관리자 넣기와 나 자신·퇴사자 빼기·입력 담당자·근무 정의·부서 출근조·점심 시각·단계) |
| 슈퍼유저 | Django 관리 화면: 근무표 만들기(또는 `add_board`)·휴장일·부서 만들기·인사이동·관리자 계정 발급과 퇴사·재직 관리자 빼기·알림 설정·로그인 잠금 해제·비상 수정. 근무표 권한은 자동으로 받지 않는다(관리 그룹에 넣어야 한다) |

- 화면에서 숨기는 것은 편의이고 서버가 모두 검사한다(서비스 첫 줄 + 근무표 범위 검사).
- 근무표 관리자는 자기 근무표에 관리자를 더하고 사람 계정을 만들 수 있으므로 권한을 나눠 주는 권한·계정을 만드는 권한이 슈퍼유저에서 관리자로 내려온다(PRINCIPLES 2026-11-16 "권한을 나눠 주는 권한은 슈퍼유저에게"를 바꾸는 결정, 결정 기록에 한 줄 + "계정을 만드는 권한을 근무표 관리자에게 준 것은 받아들인 위험"). 이유: 관리자가 바뀌거나 사람이 들어올 때마다 슈퍼유저를 거치는 것이 사용자가 말한 운영 공수다.
- 막는 것: 재직 관리자가 하나도 안 남는 빼기·퇴사(앱과 관리 화면 모두, 7.4), 재직 중인 다른 관리자 빼기, 관리자 계정의 발급·초기화·퇴사·이름 고치기. **한계**: 관리자가 자기 근무표에 아무나(그 근무표 사람·부서 없는 계정) 관리자로 넣는 것은 막지 않는다. 그렇게 넣은 일과 모든 설정 변경은 `LogEntry` 에 남아 슈퍼유저가 볼 수 있다(7.4).

## 9. 화면: 여러 근무표(5단계)

### 9.1 근무표 고르기

- 근무표가 둘 이상일 때만 보인다(하나면 지금처럼 없음). 자리는 지금 `.seg` 버튼 자리([주간]·[월간] 앞).
- Pico 의 `details.dropdown`(이미 싣고 있는 `pico.min.css` v2 기능): 닫힌 모습은 큰 버튼 하나 "근무표: <고른 이름들> ▾" — 고른 순서대로 이름을 " + "로 모두 잇고 줄바꿈을 허용한다("외 1" 처럼 감추지 않는다).
- 열면: 맨 위 [보기], 체크박스 목록(내 근무표 맨 위 "IT 당번표 (내 근무표)", 나머지 id 순), 그 위에 작게 "하나도 고르지 않으면 내 근무표만 보입니다", 맨 아래 다시 [보기](줄 전체 폭 주 버튼). **체크박스를 바꿔도 바로 보내지 않는다**(바로 보내면 드롭다운이 닫히고, 내 근무표 하나만 켠 상태에서 끄면 "아무것도 안 고름 = 내 근무표"로 돌아가 다른 근무표만 보려면 두 번 왕복해야 한다).
- GET 폼이고 숨은 칸 `pick=1`·`view`·`date` 와 지금 검색·필터 값(`q1`~`q3`, `dept`·`type`·`shift`·`hist`)을 함께 보낸다(근무표를 바꿔도 검색 색칠·필터가 남게). `pick=1` 은 "폼에서 골랐음"의 표시라 `board` 가 하나도 없으면 "아무것도 안 고름"으로 읽고 내 근무표만 보이며 기억을 비운다(`pick` 없이 `board` 도 없는 주소 = 기억한 목록). 폼을 보낸 직후 화면은 드롭다운을 연 채로 그린다(`pick=1` 일 때 `<details open>`, 고른 것을 바로 고칠 수 있게). 화면이 만드는 다른 링크에는 `pick` 을 붙이지 않는다.
- 크기: 버튼과 줄마다 높이 48px 이상, 글씨 1.05rem 이상, rem 이라 [가] 크게·아주 크게를 따른다. 체크박스는 줄 전체가 `<label>` 이라 글자를 눌러도 켜진다.
- 1400px: 드롭다운 목록은 버튼 아래 떠서 표를 가린다(닫으면 사라짐). 390px: 버튼이 한 줄 전체 폭, 목록도 전체 폭. 아주 크게 + 390px: 이름이 길면 줄바꿈(`white-space: normal`), 가로 스크롤 없음.
- 서버는 `request.GET.getlist("board")` 로 읽고, 화면이 만드는 링크도 `urlencode([("board", c) for c in codes])` 로 같은 꼴(`?board=it&board=ops`)이다. 하나만이면 지금 주소(`?board=ops`)와 같다. 없는 code 는 404(지금과 같다).
- 고르면 기억한다(`RosterPref.boards`, `/` 에서만 읽고 쓴다 — 지금 규칙 그대로). `/day/` 는 `?board=` 가 없으면 내 근무표 하나.

### 9.2 겹친 근무표 화면

- **한 길**: 근무표 하나의 날짜별 구역을 만드는 함수 하나(지금 `day_cells`·`day_info` 를 근무표 인자로)를 고른 근무표마다 부르고, 템플릿은 날짜마다 구역을 반복한다. 근무표 이름표·"보기만"·근무 없음 한 줄 같은 겹친 모양은 **고른 것이 둘 이상일 때만** 그린다. 그래서 근무표 하나면 지금 화면과 글자 하나 다르지 않다(스냅샷 테스트로 지킨다, 11절).
- 날짜 칸 = 위에서부터 휴장일 이름(한 번, 모든 근무표 공통) → 구역들. 구역 순서 = 내 근무표 먼저, 나머지 id 순.
- 구역 = 근무표 이름표(굵게, 칸 머리(`.sh`)보다 한 단계 큰 1.05em, 왼쪽 굵은 띠는 **중립색** `--pico-muted-border-color` — 링크 색(`--pico-primary`)을 쓰면 눌리는 것처럼 보인다. 바꿀 수 없는 구역은 이름표 끝에 작게 "보기만") → 그 근무표의 날 메모 → 근무조·점심당번·관제 줄(지금 `_daycell.html` 내용) 또는 "근무표 없음".
- 근무 없음 날: 둘 이상일 때는 큰 회색 상자(`.nowork`) 대신 **그 구역 안의 한 줄**("근무 없음" 또는 메모 글, 작은 여백, 굵은 본문색) — 한 근무표가 쉬는 날이 그날 전체가 쉬는 날로 읽히지 않게. 하나일 때는 지금 그대로.
- 칸 링크([바꾸기] 팝업)·[메모]는 그 구역 근무표가 바꿀 수 있는 근무표/관리하는 근무표일 때만. 링크는 그 구역 근무표의 `board_query` 를 붙여 팝업·POST 가 맞는 근무표로 간다. 나머지 구역은 보기만(서버도 `assert_can_edit`).
- 주 메모(표 위, 월간은 그 주 아래)·달 메모(표 아래): 근무표마다 따로, 앞에 근무표 이름("시장운영실 · 12/7 주 메모: …").
- 제목(`cal-title`): 둘 이상이면 날짜 범위 옆에 고른 이름들(" + ", 줄바꿈 허용). 하나면 지금 그대로.
- "보기 전용": 고른 근무표 중 바꿀 수 있는 것이 하나도 없을 때 제목 옆에(지금 규칙과 같다).
- **[내 근무표만 보기]**(`a.to-mine`, 48px 이상, `/?board=<내 근무표>` 라 기억을 비운다): 고른 목록이 정확히 [내 근무표]가 아니면 늘 보인다. 글자는 내 근무표가 목록에 있으면 "내 근무표만 보기", 없으면 지금 글자 "보기 전용 · 내 근무표로"(남의 근무표 하나를 볼 때 지금 화면과 같게).
- 월간: 칸이 길어지므로 구역 사이 간격만 줄이고(구분선 하나) **모든 구역은 이름표로 시작한다**. 모바일은 지금처럼 옆으로 민다.
- 모바일 주간(하루씩 세로): 하루 카드 안에 구역이 쌓인다.

### 9.3 검색·필터

- 이름 검색(q1~q3): 모든 구역에 색칠.
- 필터 상자 전체(부서·유형·스케줄)는 **내 근무표 구역에만** 적용한다. 규칙 하나: 근무표마다 부서·근무조·유형의 뜻이 달라서다. 필터 상자는 내 근무표가 고른 목록에 있을 때만 보이고(지금 "내 근무표가 아니면 필터 없음"과 같은 규칙), 근무표를 둘 이상 골랐을 때 머리에 "(내 근무표에만 적용)" 한 줄. 다른 구역은 늘 전체. 유형 칸은 지금처럼 내 근무표에 장중관제 정의가 켜져 있을 때만 보인다(`prefs.has_types`).
- 변경 내역 표시: 모든 구역.

### 9.4 하루 화면과 팝업

- `/day/<날짜>?board=it&board=ops`: 같은 순서로 구역을 쌓는다(휴장일 한 번, 근무표마다 날 메모·근무 없음·칸 목록, 바꿀 수 있는 구역만 [바꾸기]). 근무표 화면의 날짜 링크는 고른 목록을 그대로 넘긴다.
- 근무 변경 팝업(`/cell/`)·메모 팝업(`/memo/` 날·주·달)은 늘 근무표 하나(그 구역의 `?board=`). 팝업 링크는 **돌아갈 주소 `next`** 를 지금 화면 그대로 싣는다: 고른 근무표 전부, `view`·`date`, `q1`~`q3`, 필터, 그리고 그 칸의 앵커(`#d-2026-12-03` 같은 날짜 칸 id, 하루 화면은 칸 키). POST 는 지금처럼 `safe_next` 를 거쳐 그 주소로 돌아온다(같은 호스트 경로만). 그래서 겹친 화면에서 칸 하나를 바꿔도 고른 근무표·검색이 풀리지 않는다. **내가 바꿀 수 있는 근무표가 둘 이상**(관리하는 근무표 ∪ 내 부서의 근무표)이면 팝업 제목과 성공 메시지 앞에 "<근무표 이름> · "를 붙인다. 하나뿐이면 지금 그대로.

## 10. 마이그레이션과 업그레이드

### 10.1 전제: 운영 DB 는 02c79c5 상태

운영 서버에는 다음이 있을 수 있다고 보고 설계한다.

- 근무표: IT(`collect`) + 시장운영실 등(`direct`, `add_board` 또는 관리 화면으로 만듦).
- 회차: 모든 상태. direct 회차는 보통 취합 중(입력 중)·생성됨(확정)·배포됨, 드물게 작성 중·마감(옛 갈래가 남긴 것, 화면은 "입력 중으로만 옮기기").
- 부서: IT 부서는 입력 그룹 있음, direct 부서는 입력 그룹 없음(`input_group_id` NULL). 0023 은 그룹을 만들지 않는다(그룹 없음 = 관리자만 입력이 그대로 맞다).
- 관리 그룹·입력 그룹 멤버십, `GroupKeeper` 행(1단계 마이그레이션이 그때의 슈퍼유저를 모든 그룹에 넣었다), `RosterPref.board` 값.

업그레이드한 날 지켜야 할 것: IT 회차 흐름·문구·버튼·알림 글자(`tests/test_alarm_texts_it.py` 의 hash 포함) 그대로, 시장운영실 흐름(입력 중 → 확정 → 배포됨, 작성 중·마감 없음, [확정 취소], 채우기 버튼, 빈 평일 경고)도 그대로, 모든 멤버십 그대로, 기억한 근무표 그대로.

### 10.2 마이그레이션 파일

**0023_board_steps(1단계)** — 한 파일에 순서대로:

1. `AddField` Board `use_draft`·`use_close`(기본 참), `step_*` 다섯(기본 IT 이름) + 제약 `board_step_names_set`.
2. `RunPython(forward, backward)`(앱 코드 import 없이 `apps.get_model`. 거꾸로는 3의 `RemoveField` 가 먼저 되돌려져 `input_mode` 칸이 있는 상태에서 `backward` 가 돈다):
   - `input_mode="direct"` 근무표: `use_draft=False, use_close=False, step_collecting="입력 중", step_generated="확정"`(나머지 이름은 기본값 = 지금 `step_label` 이 끈 상태에 보이던 이름). `collect` 는 기본값 그대로.
3. `RemoveConstraint board_input_mode_valid`, `RemoveField Board.input_mode`.

거꾸로(0018~0022 처럼 **잃을 데이터가 있을 때만** 거부): `input_mode` 를 되살리고 근무표마다 채운다 — 둘 다 켬 + 다섯 이름이 IT 기본값이면 `collect`, 둘 다 끔 + 이름이 직접 입력 기본값(작성 중·입력 중·마감·확정·배포됨)이면 `direct`. 그 밖(하나만 끔, 이름을 고침)은 `input_mode` 로 나타낼 수 없어 그 근무표 code 를 알려 주며 거부("되돌리기는 업그레이드 전 백업 복원으로만"). 그래서 마이그레이션이 만든 IT 근무표만 있는 테스트 DB·지금 운영 데이터는 거꾸로 돈다.

**0024_drop_groupkeeper(3단계)** — `DeleteModel GroupKeeper` 하나. 거꾸로는 빈 표가 돌아온다(거부하지 않는다: 늘 거부하면 0024 아래로 내려가는 마이그레이션 테스트가 모두 깨진다). 행은 기록이 아니라 권한 지정이지만 사라지므로, 업그레이드 전에 참고용으로 전부 내보내 두고(10.3 ②), 3단계 롤백은 업그레이드 전 백업 복원만 지원한다(OPERATIONS 롤백 절에 적는다).

**0025_rosterpref_boards(5단계)** — `AddField RosterPref.boards`(기본 `[]`) → `RunPython(forward, backward)`: `board` 가 있는 행은 `boards=[board.code]` → `RemoveField RosterPref.board`. 거꾸로: `boards` 에 둘 이상 든 행이 있으면 거부, 하나짜리는 `board` 로 옮긴다.

2·4단계는 마이그레이션이 없다.

### 10.3 업그레이드 전 확인(읽기 전용, 운영자가 실행)

OPERATIONS "업그레이드·롤백"에 단계별로 적는다(기존 형식: `sudo -u duty sqlite3 -readonly data/db.sqlite3 "…"`, 없으면 아무것도 안 나온다).

- 1단계: 근무표별 입력 방식과 상태별 회차 수(업그레이드 뒤 같은 단계 이름으로 보이는지 대조용).
  `SELECT b.code, b.input_mode, p.status, COUNT(*) FROM duty_board b LEFT JOIN duty_period p ON p.board_id = b.id GROUP BY 1, 2, 3;`
- 2단계: 올릴 시점 확인. **IT 근무표에 취합 중·마감·생성됨 회차가 하나도 없을 때만**(작성 중·배포됨만 있을 때) 올린다. 아래가 아무것도 안 나오면 올려도 된다.
  `SELECT p.id, p.status FROM duty_period p JOIN duty_board b ON b.id = p.board_id WHERE b.code = 'it' AND p.status IN ('collecting', 'closed', 'generated');`
- 3단계 ①(올리기 전에 해결): 근무표별 재직 관리자 수. **0 인 근무표가 있으면 3단계를 올리기 전에** 관리 화면 사용자 편집의 "그룹" 칸으로 그 근무표 관리 그룹에 재직자를 넣는다(3단계부터는 재직 관리자 0명인 근무표를 앱에서 아무도 고칠 수 없고, 관리 화면도 재직 관리자를 빼는 쪽만 막으므로 넣기는 된다).
  `SELECT b.code, (SELECT COUNT(*) FROM duty_user_groups ug JOIN duty_user u ON u.id = ug.user_id WHERE ug.group_id = b.admin_group_id AND u.is_active = 1) AS active_admins FROM duty_board b ORDER BY 1;`
- 3단계 ②(내보내 둘 것): 그룹 관리자 **전부**(슈퍼유저·근무표나 부서에 걸리지 않은 그룹 포함)를 `아이디,그룹 이름` CSV 로 서버 파일에 남긴다. 0024 가 표를 지우고 거꾸로 돌려도 빈 표만 돌아온다. **3단계 롤백은 업그레이드 전 백업 복원만 지원한다**(그룹 관리자도 그대로 돌아온다). 이 CSV 는 복원 도구가 아니라 "누가 그룹 관리자였는지" 사람이 보는 참고 기록이다(아이디·그룹 이름은 바뀔 수 있으므로 자동 복원에 쓰지 않는다).

## 16. 자체 점검

- 1단계 "보이는 변화 없음": 갈래가 고르던 동작·문구·확인창은 1단계에서 임시 기준 하나(`legacy_admin_entry = not use_close`)로 지금 결과를 내고, main 기준 스냅샷과 지금 문구 테스트가 지킨다. 사용자 결정(빈 평일 경고만·채우기 모든 근무표)과 새 문구는 2단계, 늦은 입력 그룹은 3단계. 기준 함수는 3단계에서 지운다. 단계 칸 편집은 기준 함수를 지우는 3단계에서야 열리므로 임시 기준과 섞인 상태가 생기지 않는다.
- `move` 검사 순서 변경(배포됨 → 같은 상태 → `move_targets`)은 화면에서 만들 수 없는 조합의 글만 바꾸고, 네 문구는 지금 글자 그대로다(6.1).
- 2단계 문구의 단계 이름 목록은 켠 단계만 쓴다.
- 0023 은 입력 그룹을 만들지 않는다: 그룹 없음과 빈 그룹이 권한상 같고(`managed_departments`), 운영 업그레이드가 이름 겹침으로 멈출 길이 없다.
- 거꾸로 규칙은 0018~0022 와 같다(잃을 데이터가 있을 때만 거부). 0011 이 늘 IT 근무표를 만들므로 "근무표가 있으면 거부"는 모든 마이그레이션 테스트를 깨뜨린다.
- 관제 생성에서 빼는 날은 "출근 행이 하나도 없는 날"이다. 1단계에서 IT 는 빈 부서가 있으면 생성이 막혀 결과가 같고, 시장운영실(부서 하나)도 같다.
- "바꿀 수 있는 구역만 편집"은 서버 규칙(`can_edit`)과 같다. 필터는 이와 달리 늘 내 근무표 구역에만(9.3, 규칙 하나).
- 근무표 하나든 여럿이든 구역을 만드는 한 길이고, 겹친 모양은 둘 이상일 때만 그린다. 남의 근무표 하나를 볼 때 [보기 전용 · 내 근무표로] 글자도 지금과 같다(9.2).
- 근무표 고르기는 자동 제출하지 않고 `pick=1` 로 "아무것도 안 고름"과 "주소에 board 없음(기억)"을 가른다(9.1).
- 계정: 설정 화면 초기화는 연결을 남기고(`revoke_links=False`), 퇴사는 연결과 비밀번호를 끊고, 다시 재직은 [계정 발급]이 필요하며, 첫 발급 판단에 `last_login` 을 더해 기본 알림 규칙이 두 번 생기지 않는다(5.7).
- 관리자 보호 세 겹(관리자 계정은 사람 함수 대상 아님, 재직 중인 다른 관리자 빼기는 슈퍼유저, 재직 관리자 0명 금지)이 서로 모순되지 않는다. 0명 금지는 관리 화면 사용자 편집·삭제에도 같은 검사로 걸고(7.4), 이미 0명인 근무표는 3단계 전에 해결한다(10.3 ①) — 관리 화면은 빼는 쪽만 막아 넣기는 늘 된다. 남는 한계(아무나 관리자로 넣기)는 8절에 적고 `LogEntry` 로 드러낸다.
- 임시 비밀번호는 세션 메시지가 아니라 응답 본문 결과 상자라 "평문을 저장하지 않는다"와 "연달아 발급해도 앞 것을 잃지 않는다(여럿 한 번에)"를 함께 지킨다. 새로고침 재전송은 새 비밀번호를 내므로 상자 글로 막는다.
- `LogEntry` 의 `object_repr` 은 아이디·코드로 직접 넣는다(Django 5.2 `log_actions` 는 실명을 넣는다). 관리 화면 "최근 작업"은 자기 작업만 보이므로 보는 곳은 대상 페이지 [기록]이다.
- 단계 칸 편집은 임시 기준이 사라지는 3단계에서 연다(5.1). 2단계에서 열면 `use_close` 를 바꾸는 순간 입력 그룹 자동 생성 규칙이 같이 바뀐다.
- 퇴사 확인은 배포된 근무만이 아니라 배포 전 회차 행까지 센다. 막지는 않고 두 번째 확인만 받는다(6.2).
- 생성됨에서 나가는 확인창은 지금 정의가 아니라 그 회차의 실제 배정으로 글을 만든다(5.4). 정의를 끈 뒤 남은 관제 배정도 글에 나온다.
- 버튼 글자: 떼기를 못 하는 이름은 이름 전체 꼴이고, 비거나 겹치는 글자가 나오는 이름은 폼이 막는다. 기본 이름은 떼기가 되어 지금 글자 그대로다(5.4).
- 겹친 화면에서 팝업을 거쳐도 `next` 가 고른 근무표·검색·필터·앵커를 지키고, 근무표 고르기 폼도 검색·필터를 숨은 칸으로 넘긴다(9.1·9.4).
- 2단계 올리는 조건은 "IT 에 취합 중·마감·생성됨 회차가 없음"이고 10.3 쿼리가 그대로 그것을 본다.
- 0024 거꾸로는 빈 표(테스트를 위해 거부하지 않음)이고, 3단계 롤백은 백업 복원만 지원하고 10.3 ② 파일은 참고용이다.

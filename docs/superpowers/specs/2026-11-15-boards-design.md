# 근무표 일반화(여러 근무표) 설계

- 상태: 사용자 검토 대기(Codex 5차 최종 합의, 다관점 검토 반영)
- 목표: IT 당번표 하나만 다루던 앱을 **근무표 여러 개**를 다루는 앱으로 일반화하고, 시장관리본부 시장운영실 근무표를 같은 앱에서 운영한다. 나중에 시장운영실과 같은 모양(근무조 4개 이하, 시간대만 다름)의 팀이 오면 코드 변경 없이 관리 화면 설정만으로 근무표를 더한다.
- 구현이 끝나면 이 문서의 내용은 `docs/ARCHITECTURE.md`·`OVERVIEW.md`·`OPERATIONS.md`에 합치고 이 파일은 지운다.

## 1. 배경

- 지금 앱은 IT 근무 구조가 코드 상수로 박혀 있다(`duty/shifts.py`: 출근조 4개 + 장중관제 10칸 = 칸 키 14개). 근무표·변경·기록·생성·배포·통계·알림·캘린더가 모두 이 상수를 읽는다(파이썬 파일 약 20개).
- 시장운영실은 엑셀로 근무표를 만든다. 분석 결과(이름은 가려서 분석):
  - 한 팀 10~13명, 월~금. 근무조 3개: 07:30–16:30 / 09:00–18:00 / 11:00–20:00.
  - 사람마다 한 주에 한 근무조. 2026년 7월부터는 **2주마다 이른 조와 늦은 조가 맞바뀌는** 규칙이 자리 잡았다(10~11월 75% 일치. 나머지는 휴가·인원 변화·당사자끼리 맞바꿈).
  - 이름 옆에 (휴가)·(출장)·(교육), 점심당번(기본 07:30 조, 예외만 굵게), 휴장일은 칸 전체에 글, 주별 특이사항, 달별 본부 점심 명단.
  - 휴장일(공휴일·대체공휴일·선거일·임시공휴일·근로자의 날)은 근무자 0명이다.
- 보는 사람은 60세 가까운 부장들이다(변화를 싫어함, 시력이 좋지 않음).

## 2. 결정 요약

| 항목 | 결정 |
|---|---|
| 구조 | 기존 구조를 일반화한다. IT 당번표도 근무표 하나가 된다 |
| 근무표끼리 | 서로 영향이 없다. 회차 겹침·덮어쓰기 배포·배포 취소 순서·날짜의 주인은 근무표 안에서만 따진다 |
| 칸의 성격 | **키 글자가 성격을 정한다**: `dawn`·`normal`·`dinner`·`night` = 근무조, `slot0`~`slot9` = 장중관제(자동 생성, 칸당 1명), `lunch` = 점심당번(가장 이른 근무조를 따라감, 인원 제한 없음). 근무표는 쓸 키를 골라 이름·시각을 붙인다 |
| 점심당번 | IT·시장운영실 모두 칸으로 추가. 화면에는 시각 없이 "점심당번". **점심 시각은 부서마다 DB에 두고** 개인 알림·캘린더에서 쓴다(IT 4부서 11:30–12:30, 사용자 지정 값). IT는 오늘 이후 날에 새벽 근무자로 바로 채운다(알림 없이) |
| 사유 | 휴가·출장·교육. 사유가 붙으면 그날 근무로 치지 않는다(개인 알림·캘린더·점심당번 채우기·관제 자동 생성 후보·통계에서 빠짐, 근무표·보고서에는 "이름(휴가)"). 사유 변경은 이력에만, 알림 없음 |
| 근무조가 바뀔 때 점심당번 | 근무 변경 창에 "점심당번도 같이 넘기기" 체크(기본 켬) |
| 메모 | 날 메모(휴일·행사, "근무 없음"이면 그날 칸 전체를 글로 덮음), 주 메모(특이사항), 달 메모(본부 점심). 근무가 있는 날에 "근무 없음"을 달면 그날 배정을 지우고 기록·알림을 남긴다 |
| 휴장일 | **DB 표 `Holiday`**(모든 근무표 공통). 공휴일 라이브러리 + 12/31로 올해·내년을 자동으로 채우고, 슈퍼유저가 관리 화면에서 임시공휴일 추가·끄기. **다음에 만드는 회차부터**. 근무표를 만드는 도구(입력 표·채우기·관제 생성·빈 날 검사)가 건너뛴다. 이미 배정된 행은 숨기지 않는다 |
| 권한 | 그룹 기반. 근무표 관리 그룹(멤버 = 그 근무표 관리자), 부서 입력 그룹(멤버 = 그 부서 출근표 입력 담당), 그룹 관리자(멤버 넣고 빼기만) |
| 보기·바꾸기 | 모든 근무표를 서로 볼 수 있다. 바꾸기는 자기 근무표에서만(그 근무표 관리 그룹은 그 근무표를 고칠 수 있다) |
| 로그인 | 각자 계정(기존). 로그인 유지 90일(2단계, 지금 14일) |
| 화면 | 모든 근무표가 지금 모양(날짜별 칸). 근무표 고르기 버튼. "가" 버튼 글씨 크기 3단계(기기마다 기억) |
| 입력 방식 | 근무표 설정: 부서별 취합(IT) / 근무표 관리자가 직접 입력(시장운영실). 직접 입력은 기존 표를 재사용하고 [2주 전 기준으로 채우기]·[지난주와 같게] 버튼을 둔다 |
| 알림·캘린더 | IT와 같은 기능을 모든 근무표에. 1단계에서 IT 알림 문구·순서·링크는 한 글자도 바꾸지 않는다 |
| 진행 | PR 4개. 1단계는 화면·알림 변화 없음 |
| 범위 밖 | 웹 프로세스 여러 개(보류), 시장운영실 통계, 직접 지정 당번 칸, 주말 근무 칸(주 메모로 적음) |

## 4. 데이터 모델

정해진 값 칸은 `choices` + DB `CheckConstraint`, 기록을 남길 FK는 `PROTECT`(CLAUDE.md).

### 4.1 키와 성격(코드 상수, 순수 모듈 `duty/shifts.py`)

```python
KEYS = ["dawn", "normal", "dinner", "slot0", "slot1", ..., "slot9", "night", "lunch"]
#        └ 근무조 ┘ (night 도 근무조)    └ 장중관제: 자동 생성·칸당 1명·묶음 "장중관제"/"관제" ┘   └ 점심당번 ┘
```

- **순서 = 알림·캘린더·`published_days`의 칸 순회 순서.** 지금의 `CELLS`(dawn, normal, dinner, slot0..9, night)와 같고, `lunch`만 2단계에서 끝에 붙인다(1단계 `KEYS`와 제약에는 lunch가 없다). 순서를 바꾸면 알림 내용 hash가 달라져 최근 45일 알림이 다시 나간다.
- 키의 성격(코드 상수 `KIND`): `dawn`·`normal`·`dinner`·`night` = 근무조, `slot*` = 장중관제(자동 생성, 칸당 1명, 묶음 키 `slots`·이름 "장중관제"·짧은 이름 "관제"), `lunch` = 점심당번(그 근무표에서 **시작 시각이 가장 이른 근무조**에 출근한 사람이 기본, 인원 제한 없음, 혼자인 칸).
- `Commute.shift`, `DutyAssignment.cell`, `ChangeLog.cell`, `AlarmDelivery.cell`의 CheckConstraint는 이 목록의 해당 부분으로 유지한다.
- `shifts.py`의 헬퍼(`cell_label`, `cell_start/end`, `cells_of`, 묶음 판단)는 **정의 목록(defs)을 인자로 받는 순수 함수**가 된다. 기본값을 두지 않는다.
- 화면 그리는 순서: 근무조(시작 시각 순) → 점심당번 → 장중관제(키 순).
- 관리 화면의 키 선택지 표시 이름은 중립적으로 한다: "근무조 1"~"근무조 4", "관제 1"~"관제 10", "점심당번"(DB 값은 그대로). 시장운영실이 `dawn`을 "새벽"으로 오해하지 않게.
- 근무조가 5개 이상인 팀이 오면 키를 늘리는 마이그레이션을 만든다(코드 변경).

### 4.2 Board

| 칸 | 내용 |
|---|---|
| code | 짧은 영문(쿼리용), unique. IT = `it` |
| name | 화면 이름. "IT 당번표", "시장운영실" |
| input_mode | `collect`(부서별 취합) / `direct`(관리자 직접 입력). choices + 제약 |
| admin_group | OneToOne(auth.Group, PROTECT). 근무표를 저장하면 그룹을 자동으로 만든다 |

근무표 고르기 버튼은 id 순.

### 4.3 BoardShift(근무 정의)

| 칸 | 내용 |
|---|---|
| board | FK PROTECT |
| key | 4.1 목록 중 하나. (board, key) unique |
| name | 화면·CSV 이름. 근무표 안에서 unique(DB 제약 `boardshift_one_per_name`), `date`·`day`와 다르고 `(`·줄바꿈을 쓸 수 없다(CSV 열 이름이 된다) |
| start, end | 시각. 근무조·장중관제는 필수, 점심당번은 비운다(제약) |
| eligible_shifts | 장중관제만: 자격 근무조 키 목록(JSON) |
| eligible_types | 장중관제만: 자격 유형(User.type) 목록. IT = ["개발자"] |
| default_alarm | 근무조만: 새 계정의 기본 알림 규칙 대상. IT = dawn·dinner·night(지금 `DEFAULT_RULES`와 같다) |
| active | 끄기. 쓰인 정의는 지우거나 key·board를 바꿀 수 없다(관리 화면·`clean`에서 막음). 끄면 새 입력에서만 빠지고 지난 행·기록의 이름은 계속 찾는다. 코드는 `boards.active_defs`(입력 표·CSV 열, 부서 출근조·스케줄·알림 규칙 선택지, 생성)와 `boards.defs`(표시·라벨·알림 문구·캘린더 이름)로 나눠 읽는다 |

- 이름·시각을 운영 중에 바꾸면 발송 창이 열린 알림이 한 번 다시 나가고 옛 CSV의 열 이름이 맞지 않는다(help_text·운영 문서에 적는다).
- IT 근무표의 정의는 **마이그레이션 안에 값을 그대로 적어서** 넣는다(지금 `shifts.py` 상수와 같은 이름·시각·자격). 앱 코드를 import하지 않는다.
- 검증(DB 제약 + 관리 화면 FormSet.clean): 시각이 있으면 `start < end`(당일 근무만), 근무조 1개 이상, 활성 근무조끼리 시작 시각이 서로 달라야 함(가장 이른 조·이른/가운데/늦은 조가 하나로 정해지게), 장중관제·점심당번은 근무조가 있어야 함, 장중관제 자격 근무조는 그 근무표의 근무조여야 함. 오류는 한국어.

### 4.4 부서·사람

- `Department.board` FK PROTECT. 기존 4부서 = IT.
- `Department.order` 정수, NOT NULL, 기본 99(옛 `DEPT_ORDER` 밖 부서와 같이 맨 뒤). 1단계에서는 지금 `DEPT_ORDER`(근무표 부서 필터 순서)를 대체하는 데만 쓴다. Meta.ordering·다른 목록의 code 순·알림 `normalize`의 부서 정렬은 그대로 둔다(보고서 hash 불변).
- `Department.input_group` OneToOne(Group, PROTECT, null). collect 근무표의 부서만. `Department.save`가 그룹을 자동으로 만든다(픽스처·관리 화면·서비스 어느 길로 만들어도 빠지지 않게).
- `Department.managers`(M2M)는 없앤다. 1단계 호환: 같은 이름 property(`input_group.user_set`, 그룹이 없으면 빈 목록), 관리 화면 `DepartmentForm`에 `ModelMultipleChoiceField managers`를 직접 선언(초기값·후보 = 입력 그룹 기준, 퇴사 담당자 포함), `save_related`에서 `input_group.user_set.set(...)`, `filter_horizontal` 대신 `FilteredSelectMultiple` 위젯, prefetch는 `input_group__user_set`. 2단계 끝에 property를 지운다.
- `Department.lunch_start`, `lunch_end`: 점심당번 시각(null 허용, 2단계). 둘 다 비었거나 둘 다 있고 `lunch_start < lunch_end`(DB 제약 + 관리 폼). IT 4부서 = 11:30–12:30.
- `Department.shifts`(가능한 출근조)는 그대로. 관리 화면 선택지는 그 근무표의 근무조 정의에서 읽는다. 1단계에서는 저장된 부서의 근무표를 바꿀 수 없다(관리 화면에서 읽기 전용, 새 부서만 고른다). 부서를 다른 근무표로 옮기기는 필요해지면 별도 기능으로 만든다.
- 사람은 부서를 통해 근무표 하나에 속한다. 부서 없는 계정(어드민 전용)은 근무표가 없다. auto 당번 칸이 없는 근무표의 사람은 구분(User.type)을 "직원"으로 둔다(운영 문서).

### 4.5 권한

- 그룹은 Django 기본 `auth.Group`(멤버 = `user.groups`). Django permissions는 쓰지 않는다.
- `GroupKeeper(group FK CASCADE, user FK CASCADE)`, (group, user) unique.

### 4.6 회차·배정

- `Period.board` FK PROTECT. 기존 회차 = IT. `Period.overwrite_from`(덮어쓰기 시작일, 이미 있음)은 그날의 주인 계산에 쓴다(6.1).
- `Period.skip_holidays` bool(2단계): 휴장일 건너뛰기를 적용하는 회차. 새 회차 참, 기존 회차 거짓.
- `Commute`(근무조 배정)는 그대로 + `reason`(빈 값 / 휴가 / 출장 / 교육, choices + 제약, 2단계).
- `ControlDuty` → **`DutyAssignment(period CASCADE, date, cell, member PROTECT)`**. `cell` = 당번 키(`slot0`~`slot9`, 2단계부터 `lunch`).
  - unique (period, date, cell, member).
  - **조건부 unique (period, date, cell) where cell 이 `slot` 으로 시작**: 관제 칸당 한 명을 DB가 계속 보장한다.
  - 데이터 이전: `slot=n` → `cell="slot{n}"`.
- 당번 배정은 **행으로 저장한다**(읽을 때 계산하지 않는다). 점심당번 변경도 변경 기록 → 화면 → 알림 → 배포 취소의 같은 길을 탄다.
- `Period.publish_undo`(JSON) 행: `["c", period, date, member, shift, reason?]`, `["a", period, date, member, cell]`. 기존 `["k", p, d, m, n]`은 마이그레이션에서 `["a", p, d, m, "slot{n}"]`로. 여섯째 칸(reason)이 없는 행도 읽는다.

### 4.7 변경 기록

- `ChangeLog`는 그대로 + `reason_before`, `reason_after`(choices + 제약, 빈 값 허용, 2단계).
- 사유만 바뀐 기록(before == after)은 이력에는 보이고, 화면의 변경 표시(A>B·취소선)와 변경 알림에서는 건너뛴다.

### 4.8 메모

`Memo(board PROTECT, scope, date, text, no_work)`

- scope = `day` / `week` / `month`(choices + 제약). week는 그 주 월요일, month는 그 달 1일로 서비스에서 맞추고 CheckConstraint로 확인.
- (board, scope, date) unique. `no_work`는 day에만(제약).
- 메모는 회차가 아니라 (근무표, 날짜)에 붙는다. "근무표 없음"인 날에도 보인다.

### 4.9 화면·알림 설정

- `RosterPref.board` FK **SET_NULL**(보기 설정): 마지막으로 본 근무표. 필터는 본인 근무표 것만 저장한다.
- `AlarmRule.board` FK PROTECT, null 허용. 개인 규칙 = null(주인의 근무표), 보고서 규칙 = 근무표 하나(기존 행 = IT).
  - unique를 조건부 둘로: kind=personal(board 제외, 지금 칸들), kind=report(board 포함). CheckConstraint "personal → board null, report → board not null".
  - `board`를 `RULE_FIELDS`에 넣는다(따라서 `alarm_runner.SNAP`·`_key`도). 보고서 규칙의 근무표만 바꿔도 오늘 이후 발송 기록을 지운다.
- `CalendarFeed.shifts`·`RosterPref.shifts`·`AlarmRule.shifts`의 키 목록은 그대로. 장중관제 묶음은 `slots`(지금 값과 같다).

## 5. 휴장일

- **휴장일은 DB 표 `Holiday`에 둔다**(모든 근무표 공통): `date`(unique), `name`("추석" 등), `source`(`auto` 자동 동기화(라이브러리 + 12/31) / `manual` 사람이 추가, choices + 제약), `active`(끄면 휴장일이 아님).
- **자동 채우기**: 순수 모듈 `duty/market_days.py`의 `holidays_for(year) -> dict[date, str]` = 라이브러리 `holidays`(한국, 오프라인, 순수 파이썬)의 공휴일 + 매년 12/31("연말 휴장"). 서비스 `services/holidays.sync(today)`가 **(가장 오래된 회차 시작일의 해, 올해 중 이른 해)부터 (내년, 가장 늦은 회차 종료일의 해 중 늦은 해)까지**(회차가 하나도 없으면 올해~내년)의 자동 휴장일 중 표에 없는 날짜만 `auto`로 넣는다(과거 회차에도 휴장일 이름이 보이게). 동시에 불려도 안전하게 겹치는 날짜는 무시하고 넣는다(`bulk_create(ignore_conflicts=True)`). 이미 있는 행(사람이 추가하거나 끈 행 포함)은 건드리지 않는다. 라이브러리에서 사라진 날짜도 지우지 않는다(지난 기록이 바뀌지 않게, 필요하면 사람이 끈다).
  - `sync`는 몇 번 불러도 결과가 같고 가볍다(그 기간 날짜를 한 번 읽고 없는 것만 넣음). 화면을 여는 것(GET)으로는 부르지 않는다(화면 열기에 DB 쓰기를 만들지 않게). 부르는 곳:
    - 작업자(`run_worker`)가 **매 바퀴 맨 앞**(백업·변경 알림·정기 알림보다 먼저). 실패하면 로그만 남기고 다른 작업은 계속한다(지금 작업 격리 방식).
    - 휴장일이 필요한 쓰기 순간: 회차 만들기·기간 고치기(회차를 **저장한 뒤** 부른다, 그래야 그 회차의 해가 범위에 든다), 생성·확정(작업자가 꺼져 있어도 비어 있지 않게). 입력 표는 열 때(GET) 부르지 않고 표에 있는 휴장일을 그대로 쓴다(회차를 만들 때 이미 채워진다).
  - 마이그레이션은 표만 만들고 채우지 않는다(라이브러리 버전에 따라 마이그레이션 결과가 달라지지 않게).
  - 확인 결과(2025~2026): 설·추석·대체공휴일·선거일·2025-01-27 임시공휴일·2026년부터 노동절·제헌절까지 계산한다. 엑셀의 평일 휴무일 30일과 모두 맞았다.
  - 새 의존성은 이것 하나(`requirements.in`·`requirements.lock`). 업그레이드 때 라이브러리 버전을 올린다.
- **사람이 고치기**: 슈퍼유저가 Django 관리 화면 "휴장일"에서 임시공휴일을 추가(`manual`)하거나 휴장일이 아닌 날을 끈다(`active` 해제). 근무표 하나에만 해당하는 휴무는 지금처럼 그 근무표의 "근무 없음" 날 메모로 적는다.
- 휴장일을 추가·끄는 것은 배정을 지우지 않는다(이미 있는 배정은 그대로 보인다, 아래). 배포 전 회차의 입력 표는 표에 있는 휴장일을 바로 반영하고(다음에 열 때), 생성은 돌릴 때 반영한다.
- 이미 배포된 빈 휴장일을 끄면 그날은 빈 날이 된다. 근무 변경 "넣기"로 사람이 채운다(자동 보정 없음).
- 휴장일이 바뀌어 영업일 기준 알림의 발송일이 달라져도 **이미 보낸 알림은 다시 보내지 않는다**(발송 기록 hash에 발송일이 없다). 발송일이 앞당겨져 이미 지났으면 다음 바퀴에 나간다(근무 시작 전이면). 이것을 의도된 동작으로 둔다.
- 모든 근무표에서(`active`인 휴장일):
  - 날짜 칸 맨 위에 휴장일 이름.
  - **근무표를 만드는 도구가 그날을 건너뛴다**: 출근표 입력 표(그날 행 잠금), CSV(그날 이름이 있으면 오류), [2주 전 기준으로 채우기]·[지난주와 같게], 관제 자동 생성, 점심당번 채우기, 빈 날 검사(`missing_dates`·입력 현황).
  - 이 규칙은 **2단계 이후에 만든 회차**(`Period.skip_holidays` 참, 새 회차의 기본값)에만 적용한다. 2단계 마이그레이션은 기존 회차를 모두 거짓으로 둔다(사용자 결정 "다음에 만드는 회차부터"). 기존 회차의 휴장일 배정은 그대로 두고 이름만 표시한다.
  - 휴장일에 배정이 있으면 숨기지 않고 보이며 알림도 간다. 배포 뒤 근무 변경의 "넣기"로 휴장일에 사람을 넣을 수 있다(그날의 주인이 기간으로 정해지므로 행이 없어도 된다).
  - 영업일 기준 알림(`bizdays`)은 휴장일을 영업일에서 뺀다(2단계).

## 6. 흐름

### 6.1 회차와 그날의 주인

- **그날의 주인** `owner(board, d)` = 그 근무표의 배포 회차 중 `overwrite_from ≤ d ≤ end_date`인 것 가운데 **가장 최근에 배포한 것**. 순서: 배포 `PeriodEvent` 순번(배포 이벤트가 없는 옛 회차는 이벤트가 있는 회차보다 오래된 것으로 보고, 그들끼리는 `published_at`, 그다음 pk 순). 배포할 때 다른 회차의 [S 이후] 행과 이 회차의 [S 이전] 행을 지우는 지금 규칙과 같은 결과다. 배정 행이 없어도 주인이 있다(근무 없음으로 비운 날, 배정 없는 휴장일).
  - `_owner`(근무 변경), `published_days`(근무표·알림·캘린더), `change_notice._live`(그 기록의 회차가 아직 그날의 주인인가), 이력 숨김 판단, 배포 미리보기(`preview_publish`의 대상 회차 이름·폐기될 변경 기록 수)가 모두 이 함수 하나를 쓴다.
  - 기존 배포 회차 중 `overwrite_from`이 비어 있으면 마이그레이션에서 `start_date`로 채운다.
  - `published_days`는 주인이 있는 평일을 모두 만든다(행이 없으면 빈 칸). 단 정기 알림(`plan`)에는 배정이 하나도 없는 날을 넘기지 않는다(빈 보고서가 나가지 않게). 변경 알림은 그대로. 지금은 행이 있는 날만 만든다. IT에서는 배포된 평일에 늘 행이 있어 화면 차이가 없다(1단계 테스트로 확인).
- 겹침 검사, `missing_dates`, 입력 현황은 `board=period.board`로 거른다.
- **배포**: `publish._others`에 `.filter(board=period.board)`. 미리보기·배포·배포 취소가 이 함수를 쓴다. 빠지면 시장운영실을 배포할 때 IT의 같은 기간 행이 지워진다. 테스트로 고정한다.
- 배포 취소 순서는 근무표마다 센다(`period__board=period.board`). `log_floor`는 전역 번호 비교라 그대로 맞다.
- 배포 취소로 `publish_undo`를 되살릴 때, 그 근무표의 "근무 없음" 날짜 행은 되살리지 않는다(근무 없음 날은 늘 비어 있다). 배포 취소 화면의 복원 행 수(`UnpublishInfo`)도 그 행을 빼고 센다.
- 생성됨에서 나갈 때(`periods.move`) 당번 배정을 모두 지운다(지금과 같다).
- DB 상태 5개와 제약은 그대로. 화면 단계를 input_mode에 따라 묶는다:
  - collect(IT): 작성 중 → 취합 중 → 마감 → 생성됨 → 배포됨(지금 그대로).
  - direct(시장운영실): **입력 중 → 확정 → 배포됨**. 새 회차는 만들자마자 취합 중(화면 이름 "입력 중"). 입력 중에도 기간을 고칠 수 있다(`save_draft`가 direct에서는 취합 중도 허용, 줄이면 기간 밖 행을 지움). [확정] = 생성(6.3). [확정 취소] = 입력 중으로.

### 6.2 출근표 입력

- 출근표는 지금처럼 부서 단위 표다. direct 근무표는 "부서 하나짜리 근무표"로 만들어 표·CSV·검증(`collect.apply_table`)을 그대로 쓴다.
- 입력할 수 있는 사람: collect = 부서 입력 그룹 + 근무표 관리 그룹, direct = 근무표 관리 그룹.
- 서비스 `collect._require_input`에 `period.board == dept.board` 검사(CSV 경로도 막힌다). 목록은 근무표가 같은 회차·부서만 짝짓는다.
- 지난 날짜 검사는 `perms.is_board_admin(user, period.board)`(지금 `is_admin` 두 곳: services/collect.py, views/collect.py).
- CSV·오류 문구는 근무 정의 이름(`{key: name}`, 화면 순서)을 인자로 받는다. IT 이름은 지금 라벨과 같아 기존 CSV가 그대로 읽힌다(테스트로 고정).
- 입력 키는 `collect.input_keys(dept)` 하나로 정한다: 부서 출근조 가운데 켜진 근무조 정의가 있는 것. 입력 표 칸·머리글·POST·CSV 열·검증이 모두 이것을 쓴다. 저장은 꺼진 근무조 정의의 기존 배정만 남기고 그 부서의 나머지 행을 바꾼다(그 사람을 그날 다른 근무조에 다시 넣으면 검증 오류). 부서 출근조에서 뺀 근무조(정의는 켜짐)의 행은 지금처럼 저장 때 지운다(입력 칸이 없어 남기면 아무도 못 지운다).
- 서비스 `load_table`·`export_csv` 도 근무표 짝을 검사하고, 화면(`views/collect._load`)은 짝이 다르면 404.
- 사유(2단계): 표·CSV에서 `이름(휴가)`로 적는다. 끝이 정확히 `(휴가)`·`(출장)`·`(교육)`일 때만 사유로 떼어 읽는 순수 함수. `validate_member_name`에 "끝이 (사유)인 이름 금지"를 더하고, 2단계 마이그레이션은 이미 그런 이름의 계정이 있으면 이름을 알려 주며 멈춘다.
- 채우기 버튼(3단계, direct 근무표, 주마다):
  - **[2주 전 기준으로 채우기]**(근무조가 정확히 3개일 때만 보인다): 시작 시각으로 이른·가운데·늦은 조를 정한다. 2주 전 그 주의 사람별 대표 근무조(근무로 친 날이 가장 많은 근무조. 같으면 그 후보 중 그 주에 먼저 나온 근무조, 그래도 같으면 시작 시각이 이른 근무조)를 구해, 이른 → 늦은, 늦은 → 이른, 나머지·2주 전 근무가 없던 사람 → 가운데로 월~금에 채운다. 이번 주 휴장일·근무 없음 날은 비운다. 지금 재직하고 그 근무표 부서에 있는 사람만.
  - **[지난주와 같게]**: 지난주 같은 요일을 그대로(사유 제외). 지금 재직하고 그 근무표 부서에 있는 사람만.
  - 기준 데이터: 날짜마다 지금 회차 기간 안이면 이 회차의 표, 밖이면 배포된 근무표(그날의 주인)를 읽어 합친다.
  - 누르면 **그 주(회차 기간 ∩ 그 주 월~금)의 줄을 채운 표를 그려서 보여 주기만** 한다(바뀌는 칸은 색으로 표시). 다른 주는 그대로. 저장은 [표 저장]과 기존 검증을 거친다.

### 6.3 생성·확정(당번 채우기)

`run_generation`(collect의 생성, direct의 확정). 한 트랜잭션:

1. 그 회차의 당번 배정을 모두 지운다(지금과 같다).
2. **장중관제**: 그 근무표의 `slot*` 정의가 있으면 `generator`로 채운다. 후보 = 그 근무표 부서의 재직자 중 `eligible_types`에 맞고 그날 자격 근무조에 **근무로 친** 출근이 있는 사람. 한 사람 하루 한 관제 칸.
3. **점심당번**: 그 근무표에 `lunch` 정의가 있으면 날짜마다 가장 이른 근무조에 근무로 친 출근을 한 사람 전원. 아무도 없으면 비우고 경고.

- 근무 없음 날, 그리고 `period.skip_holidays`가 참일 때의 휴장일은 2·3에서 뺀다. `slot*`가 없는 근무표는 generator를 부르지 않는다.
- 점심당번 채우기는 무작위를 쓰지 않는다. 같은 씨앗이면 IT 관제 결과가 지금과 똑같다.
- 상태: collect는 마감·생성됨에서(지금처럼, 빈 날이 있으면 오류 — 그 근무표 부서만, `skip_holidays`면 휴장일 제외). direct는 취합 중(입력 중)·생성됨에서, 빈 평일은 **경고 목록**으로 돌려준다(오류 아님).
- `generator.py`(순수)는 인덱스 기반을 그대로 두고 칸 목록 `[(라벨, 자격 근무조, 자격 유형)]`(유형 빈 튜플 = 전원)을 **필수 인자**로 받고, 후보를 칸마다 거른다(그 칸 자격 근무조에 출근 ∧ 그 칸 자격 유형). 사람은 `{유형: 사람}` 으로 받는다(기본값 없음). 인덱스 ↔ 키 변환은 `services/generate.py`. 기존 generator 테스트는 IT 관제 목록을 인자로 넘기도록 준비 코드만 고친다.

### 6.4 근무 변경

- `_owner(board, d)` = 6.1의 그날의 주인. `change_cell`·`exchange`·`swap`이 board를 받는다(화면의 `?board=`, 없으면 내 근무표).
- 서비스 공개 함수 첫 줄에 `perms.assert_can_edit(user, board, d)`: user 부서의 근무표 == board 이거나 그 근무표 관리 그룹. 지난 날짜는 관리 그룹만. 일반 멤버는 자기 근무표의 누구 칸이든 바꾼다(지금 IT와 같다).
- 들어오는 사람은 그 근무표 부서 사람이어야 한다(`_check_candidate`). 빼기만은 허용(부서를 옮긴 사람의 옛 행 정리).
- 장중관제 칸은 지금처럼 교체만. 점심당번은 넣기·빼기·교체. "같은 날 다른 칸도 맡음" 경고와 맞교환의 다른 칸 개수 검사는 **같은 묶음 안**으로 좁힌다(점심과 관제가 서로 맞교환되지 않게).
- 자격 경고(`_eligibility_warnings`)는 정의의 `eligible_shifts`·`eligible_types`·`name`을 읽는다.
- **점심당번 같이 넘기기**(2단계): 근무조 칸 변경 창에 "점심당번도 같이 넘기기" 체크(기본 켬, 그 근무표에 lunch 정의가 있을 때만 보임). 켜고 저장하면, 떠나는 사람이 그날 점심당번이고 들어오는 사람은 아닐 때 같은 트랜잭션에서 점심당번을 넘기고 `ChangeLog(cell='lunch')`를 근무조 기록 **뒤에** 남긴다(변경 알림의 맞교환 짝짓기가 깨지지 않게, 테스트로 고정).
- **사유 바꾸기**(2단계): `changes.set_reason(user, board, d, member, reason)`. 근무조 칸 변경 창에 사유 선택(없음/휴가/출장/교육). `ChangeLog`에 reason_before/after, 변경 알림 없음. 그 사람이 그날 점심당번이면 "점심당번 칸에 남아 있습니다. 다른 사람으로 바꾸세요" 경고(자동으로 빼지 않는다). 이미 보낸 개인 알림은 되돌리지 않는다.
- 근무조 칸 변경의 "부서 가능 출근조 검사"는 1단계에 넣지 않는다(지금 IT 동작이 바뀐다).
- 배포된 날짜를 바꾸는 길은 근무 변경 하나뿐이다. 입력 표는 배포 전 회차만 고친다.
- 근무 없음 날에는 근무 변경을 막는다("근무 없는 날입니다"). 휴장일은 막지 않는다.

### 6.5 메모와 근무 없음

- 메모 편집은 그 근무표 관리 그룹만. 날짜 칸·표 위의 [메모] 팝업(근무 변경 창과 같은 방식).
- **"근무 없음" 날 메모를 저장할 때 그날 배정이 있으면**: 확인창("○명의 근무가 지워집니다") → 저장하면 그날 모든 배정(근무조·당번)을 지우고 지운 것마다 `ChangeLog`를 남긴다. 그날의 주인은 기간으로 정해지므로 남아 있고, 변경 알림은 평소처럼 나간다(`_live`가 주인 기준). 지난 날짜면 관리 그룹만.
- 메모를 지우거나 "근무 없음"을 끄면 그날은 빈 날이 되고, 근무 변경 "넣기"로 다시 채운다.
- 배포 전 회차에서도 근무 없음 날은 휴장일과 같이 다룬다(`skip_holidays`와 상관없이 늘): 입력 표 그날 행 잠금, CSV에 그날 이름이 있으면 오류, 채우기 버튼·생성에서 빼고, `missing_dates`·입력 현황에서도 뺀다.

## 7. 화면

- 넘기는 데이터 모양(`day_info`의 cells → `_daycell`/`_cellbody`/`_labels`)은 그대로. 어떤 칸을 어떤 순서·묶음·이름으로 그릴지만 정의에서 읽는다.
- **1단계에는 사용자 화면이 한 글자도 바뀌지 않는다.** 근무표가 하나면 고르기를 그리지 않고, 묶음 제목은 "관제"·"장중관제", "출근조" 같은 제목도 지금 글자 그대로. 링크는 `?board=` 없이 지금 그대로. (예외: 슈퍼유저 전용 Django 관리 화면은 바뀐다 — 사용자 목록·필터의 스태프 → 그룹, 부서 화면.)
- 근무표 고르기(2단계): 근무표 화면(`/`)의 보일 근무표 = `?board=` → `RosterPref.board` → 내 부서의 근무표 → 내가 관리하는 첫 근무표 → 첫 근무표. `RosterPref.board`(마지막에 본 근무표)는 `/` 에서만 읽고 쓴다: /day/·/cell/·/memo/ 와 알림 링크는 `?board=` 가 있을 때만 그 근무표이고 없으면 내 근무표다. 주소 모양은 그대로(/, /day/, /cell/, /memo/가 board를 쿼리로). 날짜 이동·필터 폼·htmx·변경 POST의 URL은 공통 함수로 만들고, **보이는 근무표가 내 근무표가 아닐 때만** `?board=`를 붙인다. 버튼은 주간/월간 앞 `.seg`.
- **보기 전용** = 내 근무표도 아니고 그 근무표의 관리자도 아닐 때: 제목 옆 "보기 전용", 칸 링크·"칸을 누르면…" 안내·[바꾸기] 숨김. 내 근무표가 아니면(관리자라도) 필터 없이 전체를 보이고 본인 필터를 덮어쓰지 않는다.
- 날짜 칸: 근무조 → 점심당번 → 관제. 사유는 지금 배정된 사람 이름 뒤 작은 "(휴가)"(변경 내역을 꺼도 보인다). 휴장일·날 메모는 칸 맨 위 한 줄, 근무 없음이면 칸 전체를 메모 글로 덮는다.
- 주 메모는 표 위(월간은 그 주 행 아래), 달 메모는 표 아래. 관리 그룹에게만 [메모] 링크.
- 부서 필터는 그 근무표 부서만, `Department.order` 순. 유형 필터는 `slot*` 정의가 있는 근무표에만. 스케줄 선택지 = 그 근무표의 근무조 키 + `slots`(관제가 있으면) + `lunch`(있으면).
- **글씨 크기**(2단계): 오른쪽 위 화면 모드 버튼 옆 "가" 버튼. 보통 → 크게(×1.15) → 아주 크게(×1.3) 순환. `localStorage`(`duty-size`) + `<html data-size>`, 테마와 같은 head 스크립트로 깜빡임 없이. 1400px·390px에서 "아주 크게 + 월간"을 브라우저로 확인한다.
- 회차 화면: 목록·새 회차는 내가 관리하는 근무표만(새 회차 폼에서 근무표 고르기, 하나면 숨김). 상세는 input_mode에 따라 단계·버튼(direct: [표 입력] [확정] [확정 취소], 입력 현황·편차 표·생성 방식은 숨김, 확정 경고 목록 표시). 편차 표는 `slot*`가 있을 때만.
- 근무 변경 창: To 후보 = 그 근무표 부서의 재직자. 점심당번은 넣기만·빼기만도 보인다. 근무조 칸에는 사유 선택과 "점심당번도 같이 넘기기"(2단계).
- 그룹 화면(3단계): 메뉴 [그룹]은 GroupKeeper에게만. 내가 맡은 그룹의 멤버를 보고 넣고 뺀다(후보 = 재직 계정, 퇴사자는 "(퇴사)"로 보여 뺄 수 있게). 관리 그룹 멤버를 다 빼면 경고만.
- Django 관리 화면(슈퍼유저): Board + BoardShift·GroupKeeper 인라인(4.3 검증, 편집은 3단계. 1단계는 보기만). 그룹 화면은 permissions 칸을 숨긴다(1단계는 이름과 보기 전용 그룹 관리자). 1단계 관리자 지정은 사용자 화면의 groups 칸. UserAdmin은 user_permissions 숨김, 목록·필터의 is_staff → groups. DepartmentForm은 4.4.
- 메뉴: 회차·이력 = 어느 근무표든 관리 그룹(`perms.is_admin`), 통계 = `slot*`가 있는 근무표의 관리 그룹, 출근표 입력 = 입력할 수 있는 부서가 있을 때, 그룹 = GroupKeeper, 관리 = 슈퍼유저(그대로). 근무표 화면의 편집 판단(주간·월간 칸 링크, 하루 화면 [바꾸기])은 `perms.can_edit(user, board, d)`.

## 8. 알림·캘린더·통계

### 8.1 알림

- **1단계에서 IT 알림 문구·칸 순서·링크는 한 글자도 바꾸지 않는다.** IT 정의로 만든 개인·보고서 문구 전체가 지금 문자열과 같은지 테스트로 고정한다(보고서 본문 전체 포함).
- `alarms/`(plan, schedule, messages)는 정의 목록을 인자로 받는다(순수 모듈 유지). 이름은 정의에서, 묶음 이름은 `KIND` 상수. 순회 순서는 `KEYS`.
- **`alarm_runner.collect`는 근무표마다 `plan`을 따로 부른다.** 그 근무표의 `published_days`와 그 근무표 규칙만 넘긴다(개인 = 주인 부서의 근무표, 보고서 = `rule.board`, 부서 없는 계정의 개인 규칙은 넘기지 않음). `extra_dates`도 그 규칙들의 발송 기록 날짜만. 같은 날짜에 다른 근무표가 있어도 IT 개인 규칙이 취소 알림을 내지 않는다(테스트로 고정).
- 보고서의 이름 단위 거르기(`plan`의 keep)는 그대로(부서 없음·퇴사자의 근무도 보고서에 남는다). 부서 선택지와 `normalize` 검사만 그 근무표 부서로.
- 사람의 부서를 바꿔 근무표가 달라지면(사용자 저장 서비스, 관리 화면 저장이 부른다) 그 사람 개인 규칙의 오늘 이후 `AlarmDelivery`를 지운다(옛 근무표의 발송 기록으로 취소 알림이 나가지 않게, 테스트로 고정).
- 기본 규칙: `create_defaults`는 지금 `DEFAULT_RULES`(코드 상수, 전날 18시·시작 2시간 전)의 시점을 쓰고, 대상 근무조는 그 사람 근무표에서 `default_alarm`이 켜진 근무조 키를 **명시적으로** 저장한다(`[]`는 관제·점심당번까지 포함한 "전체"라서 쓰지 않는다). IT는 dawn·dinner·night(지금 값과 같다), 시장운영실은 세 근무조 전부(세 조가 모두 교대 근무라서). 근무표 없는 계정은 지금 상수 그대로.
- `normalize`는 키·부서를 그 근무표 기준으로 검사. plan·calendar는 모르는 키를 조용히 무시한다.
- 알림 규칙 화면: 근무표가 하나면 근무표 칸을 숨기고 IT로 고정. 부서 선택지·"전부" 기본값은 고른 근무표의 부서.
- 링크: 1단계는 지금 그대로(`/day/<d>/`). 2단계부터 알림의 근무표가 받는 사람의 근무표와 다를 때만 `?board=<code>`(보고서 규칙이 남의 근무표일 때, 변경 알림). 같으면 그대로라 IT 알림 hash에 영향이 없다.
- **점심당번**(2단계):
  - 문구 틀은 셋: 근무조(지금 그대로), 묶음 당번 칸(지금 관제 그대로), 혼자인 당번 칸(점심당번 — 개인 알림 "점심당번"(부서 시각이 있으면 시각 포함), 보고서 줄 "점심당번 이름…", 변경 알림 위치 "점심당번"). 정확한 문구는 2단계 문구 고정 테스트로 정한다.
  - 개인 알림의 점심당번 시작 = 그 사람 부서의 `lunch_start`. 시각이 없으면 시각 기준 규칙에서 빼고 날짜 기준 규칙에는 넣는다.
  - 보고서는 점심당번 줄을 기존 줄 **뒤에** 시각 없이 붙이고, 발송 창·만료 계산(첫·마지막 시작 시각)과 `same_day_notice`에서 점심당번을 뺀다. 보고서 규칙에서 **점심당번만 고르는 것은 저장 때 막는다**(시각이 있는 칸이 하나 이상 있어야 한다).
  - 시각이 없는 점심당번이 들어간 개인 날짜 기준 알림의 만료는 그날 끝(다음 날 00:00)이다.
  - 2단계 배포 때 IT 보고서 규칙의 내용이 바뀌어 그날 발송 창이 열린 보고서가 한 번 다시 나간다(결정 기록에 적는다).
- 사유가 있는 배정은 개인 알림에서 빼고, 보고서에는 "이름(휴가)".
- 변경 알림(`change_notice`)은 `r.period.board`의 정의로 문구. `_live` = 그 기록의 회차가 아직 그날의 주인인가(6.1). 사유만 바뀐 기록은 건너뛴다.
- 영업일 기준 알림은 휴장일을 영업일에서 뺀다(2단계).

### 8.2 캘린더

- 구독 주소·토큰·일정 UID 형식(날짜-키-pk)은 그대로.
- 사용자 근무표의 정의로 이름·시각. 필터는 `slots` 또는 키.
- 점심당번은 부서 점심 시각이 있으면 일정 하나("점심당번"). 사유가 있는 날은 빠진다.

### 8.3 통계

- `stats`는 그 근무표의 `slot*` 정의로 센다. IT 열과 동작은 그대로(근무로 친 배정만 — 2단계 전에는 사유가 없어 같다). 점심당번은 횟수에 넣지 않는다.
- 통계는 `slot*`가 있는 근무표만. 시장운영실 통계는 이번에 만들지 않는다.

  - `managed_departments(user)` = (입력 그룹 멤버인 부서) ∪ (내가 관리하는 근무표의 모든 부서). 1단계에 IT 관리자의 [출근표 입력] 메뉴와 전 부서 목록이 그대로 남는다.
  - `can_edit(user, board, d)` / `assert_can_edit`.
  - 슈퍼유저라고 자동으로 통과시키지 않는다. 슈퍼유저는 근무표·그룹 생성, 첫 그룹 관리자 지정, 계정 발급, 알림 설정(관리 화면)을 한다.
- 회차를 다루는 뷰는 `_period(request, pid)` 도우미 하나로 `is_board_admin(user, period.board)`를 검사(아니면 404).
- 통계·이력·회차 화면은 내가 관리하는 근무표만. 이력의 근무표 열과 필터는 2단계(1단계는 거르기만). 이력의 칸 이름은 `log.period.board`의 정의로.
- 도움말 영상 권한: manager 영상 = 입력할 수 있는 부서가 있는 사람, admin 영상 = 어느 근무표든 관리자(지금과 같은 뜻인지 테스트로 확인).
- 로그인 유지(2단계): `SESSION_COOKIE_AGE` 90일(로그인할 때부터, 요청마다 늘리지 않음 — 화면을 열 때 DB 쓰기를 만들지 않게). 비밀번호 변경·초기화 때 끊기는 것은 그대로.

## 10. 마이그레이션

SQLite라 스키마 변경과 데이터 이전을 파일로 나눈다. 운영 롤백은 업그레이드 절차 첫 줄의 백업 복원이 기본이다.

### 1단계

1. 스키마: Board, BoardShift, GroupKeeper, DutyAssignment, `Period.board`·`Department.board`·`Department.input_group`·`AlarmRule.board`·`RosterPref.board`(null 허용), `Department.order`(NOT NULL 기본 99).
2. 데이터(RunPython):
   - 그룹은 `Group.objects.create`로 만든다. **이름이 이미 있으면 그 이름을 알려 주며 멈춘다**(뜻이 섞이지 않게).
   - IT 근무표("IT 당번표", code `it`)와 "IT 근무표 관리" 그룹, IT 정의 14행(값을 직접 적음, default_alarm = dawn·dinner·night).
   - 모든 부서·회차에 board=IT, 부서 순서. 배포 회차의 비어 있는 `overwrite_from` = `start_date`.
   - `is_staff`인 사람을 IT 관리 그룹에. 부서마다 "<부서> 출근표 입력" 그룹을 만들고 managers를 옮긴다.
   - 지금 슈퍼유저 전원을 이 그룹들의 그룹 관리자로.
   - ControlDuty → DutyAssignment(`slot{n}`), `publish_undo`의 `k` 행 → `a` 행.
   - 보고서 알림 규칙에 board=IT. 저장된 `AlarmRule.depts`는 다시 정규화하지 않는다.
   - reverse: 입력 그룹 멤버 → managers, DutyAssignment → ControlDuty, `a` → `k`, board·input_group·admin_group을 비운 뒤 GroupKeeper·BoardShift·Board·이 마이그레이션이 만든 그룹 삭제.
3. 스키마: `Department.managers`·ControlDuty 삭제(managers 삭제 직전에 근무표 없는 부서를 IT 로 옮기고 입력 그룹·담당자를 복사), `Period.board`·`Department.board` NOT NULL(근무표 없는 회차는 IT 로 채우고, 근무표 없는 부서가 남아 있으면 멈춘다), 새 제약.
- `is_staff` 값은 바꾸지 않는다(관리자 판정에는 더 쓰지 않는다).

### 2단계 (되돌리기는 백업 복원으로만)

- 스키마: `Holiday`, `Commute.reason`, `ChangeLog.reason_before/after`, Memo, `Department.lunch_start/end`, `KEYS`에 lunch와 관련 제약, `Period.skip_holidays`. `skip_holidays`는 기존 행에 거짓이 들어가도록 `default=False`로 추가하고(데이터 이전 불필요), 같은 마이그레이션 파일 안에서 다음 단계로 모델 기본값을 참으로 바꾼다(이후 만드는 회차는 참).
- 데이터:
  - 이름이 `(휴가)`·`(출장)`·`(교육)`으로 끝나는 계정이 있으면 멈춘다.
  - IT에 점심당번 정의, IT 4부서 점심 11:30–12:30.
  - **오늘(포함) 이후 날짜에서 배포됨·생성됨 회차의 새벽 근무자(사유 없음)를 점심당번으로 채운다**(ChangeLog·알림 없음). 배포됨 회차의 `publish_undo`에 있는 새벽 `c` 행(오늘 이후)에도 같은 규칙으로 lunch `a` 행을 더한다(배포 취소로 되살아난 날에도 점심당번이 있게). "오늘" = 마이그레이션이 도는 날(Asia/Seoul).
- 운영에 점심당번이 생기면 lunch 행·기록·설정이 쌓이므로 reverse는 만들지 않는다(마이그레이션에 명시).

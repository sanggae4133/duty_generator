# 아키텍처

코드가 지금 어떻게 생겼고 왜 그런지를 적는다. 기획은 [OVERVIEW.md](OVERVIEW.md), 설계 철학·결정 기록은 [PRINCIPLES.md](PRINCIPLES.md), 운영 명령은 [OPERATIONS.md](OPERATIONS.md), 개발 방법은 [DEVELOPMENT.md](DEVELOPMENT.md). 이 문서와 코드가 다르면 코드가 맞고, 이 문서를 고친다.

## 한눈에

```
브라우저 ──▶ gunicorn(duty-web) ──▶ Django 앱 duty ──▶ SQLite (data/db.sqlite3)
                                                         ▲
작업자 run_worker(duty-worker) ── 1분마다: 휴장일 채우기 → 백업 → 상태 점검 → 변경 알림 → 정기 알림 발송(텔레그램·웹 푸시)
캘린더 앱 ──▶ /calendar/<토큰>.ics (로그인 없이, 토큰으로)
```

- 앱 프로세스는 웹과 작업자 두 개뿐이다. 둘 다 같은 코드, 같은 `.env`, 같은 `data/`를 쓴다. 웹 앞에는 nginx 가 있다(설정 `deploy/duty-nginx.conf`, 느린 연결을 대신 받아 준다).
- 외부 연동 API는 없다. 바깥으로 나가는 것은 텔레그램 Bot API와 웹 푸시뿐이다.
- Tailscale Funnel로 공개된다(인터넷 → Funnel → nginx 127.0.0.1:8008 → gunicorn 127.0.0.1:8090). 모든 권한은 서버에서 검사한다(화면에서 버튼을 숨기는 것은 편의일 뿐).

## 데이터

```
Board(근무표) ─< BoardShift(근무 정의: 키·이름·시각·자격)
      ─< Department ─< User(멤버 겸 로그인 계정)
      ─< Period ─< Commute(날짜·멤버·출근조·사유)    Period ─< PeriodEvent(상태 기록)
                ─< DutyAssignment(날짜·칸·멤버)      Period ─< ChangeLog(근무 변경 기록, 사유 전후)
      ─< Memo(날·주·달 메모, 근무 없음)
Holiday(휴장일, 모든 근무표 공통)
auth.Group: Board.admin_group(근무표 관리), Department.input_group(출근표 입력, 첫 담당자를 넣을 때 생긴다)
User ─ RosterPref(boards: 고른 근무표 code 목록) · CalendarFeed · TelegramAlarmProfile · PushAlarmSubscription · AlarmRule(─ Board) ─< AlarmDelivery
AlarmSettings(한 행: 봇 토큰, 장애 알림 chat_id, 푸시 키)
```

- **Board**(근무표): IT 당번표(`code="it"`, 마이그레이션이 만든다)에 더해 관리 화면·`add_board` 로 근무표를 더 만들 수 있다. 부서·회차·근무 정의·보고서 알림 규칙이 근무표에 속하고, 사람은 부서를 통해 근무표 하나에 속한다(부서 없는 계정은 근무표 없음, `boards.board_of(user)`). 근무표마다 회차 단계 설정(`use_draft`·`use_close`, 다섯 단계 화면 이름 `step_*`, 아래 "회차")이 있다. 근무표를 만들면 관리 그룹 "<이름> 근무표 관리"가 저절로 생긴다. 부서의 입력 그룹 "<부서> 출근표 입력"은 **첫 입력 담당자를 넣을 때** 생긴다(`Department.ensure_input_group`: [근무표 설정]의 `board_settings.add_assignee` 와 관리 화면 부서 폼. 같은 이름의 그룹이 이미 있으면 "같은 이름의 그룹이 이미 있습니다: …. 슈퍼유저에게 그 그룹 이름을 바꿔 달라고 하세요."로 막는다). 입력 그룹이 없는 부서와 빈 그룹인 부서는 똑같이 "근무표 관리자만 입력"이다(`perms.managed_departments`). 그룹 이름은 근무표·부서 이름을 **바꿀 때만** 따라간다: 이름을 바꾸면 같은 저장에서 그룹 이름도 "<새 이름> 근무표 관리"·"<새 이름> 출근표 입력"이 되고(그 이름의 다른 그룹이 있으면 관리 화면이 이름 칸 오류로 막는다), 이름을 안 바꾼 저장(근무 정의만 고친 저장 등)은 그룹 이름을 건드리지 않는다. 그래서 마이그레이션이 만든 IT 근무표("IT 당번표")의 관리 그룹 "IT 근무표 관리"는 그대로 남고, 관리 화면 "그룹"에서 따로 바꾼 그룹 이름도 다음 이름 변경 때까지 유지된다. 회차 겹침·배포·배포 취소·그날의 주인·알림 계산은 근무표 안에서만 따진다. 서비스 함수는 근무표를 명시 인자로 받는다.

- **User**: `username` = 멤버 코드. `department`가 없으면 근무표에 안 나오는 관리 전용 계정. `is_active`(재직)를 끄면 근무표 후보에서 빠지고 로그인도 막힌다. 지난 근무·기록·통계에는 남는다. 근무표 후보는 `User.objects.roster()`.
- 이름(`User.name`)은 전체에서 고유하다. `>` `,` 줄바꿈 금지, `+`로 시작 금지(변경 체인·CSV 문법 문자).
- 서비스는 트랜잭션에 들어가자마자 회차를 다시 읽어(`refresh_from_db`) 화면이 읽은 오래된 상태로 결정하지 않는다.
- 정해진 값만 받는 칸은 `choices` + DB `CheckConstraint`(SQLite엔 enum이 없다). 기록을 남겨야 하는 FK는 `PROTECT`라서 근무·기록이 있는 사용자·회차는 지울 수 없다(비활성화한다).
- SQLite는 WAL, 트랜잭션은 `IMMEDIATE`(쓰기가 서로 줄 선다). 웹은 gunicorn 워커 1개·스레드 4개.

## 근무표와 칸

칸(cell) 키는 코드에 고정된 목록 `shifts.KEYS`(dawn, normal, dinner, slot0~slot9, night, lunch)이고 화면·기록·알림이 똑같이 쓴다. 이 순서가 알림·캘린더·`published_days`의 순회 순서다(바꾸면 알림 내용 hash가 달라져 최근 알림이 다시 나간다).

- **키 글자가 성격을 정한다**(`shifts.kind`): `dawn`·`normal`·`dinner`·`night` = 근무조(`SHIFT`, `SHIFT_KEYS`, 한 사람 하루 하나, DB 제약), `slot0`~`slot9` = 장중관제(`SLOT`, `SLOT_KEYS`, 자동 생성, 칸당 1명, 묶음 키 `slots`·이름 "장중관제"·짧은 이름 "관제"), `lunch` = 점심당번(`SOLO`, 혼자인 당번 칸, 인원 제한 없음, 정의에 시각이 없다). 같은 성격끼리만 맞교환한다.
- 근무표는 쓸 키를 골라 이름·시각·자격을 붙인다(`BoardShift`, 근무 정의). IT 정의는 마이그레이션이 그전 값을 그대로 넣었다: 새벽 06:30~15:30, 정상 08:00~17:00, 석식교대 09:00~18:00, 야간 13:30~21:30, 장중관제 10칸(08:30~18:00, 자격 출근조는 08:30 칸 = 정상, 17:00 칸 = 석식교대, 나머지 = 정상·석식교대, 자격 구분 = 개발자), 기본 알림 대상 = 새벽·석식교대·야간. 끈 정의(`active`)는 새 입력(입력 표·CSV 열, 부서 출근조·스케줄·알림 규칙 선택지, 생성)에서 빠지고(`boards.active_defs(board)`), 표시·지난 행·기록의 이름 찾기에는 남는다(`boards.defs(board)`는 꺼진 것까지 KEYS 순으로 돌려준다).
- `shifts.py`의 헬퍼(`cell_label`·`cell_start`·`cell_end`·`cells_of`·`display_order`·`shift_defs`·`slot_defs`)는 정의 목록을 첫 인자로 받는 순수 함수다. 기본값이 없다. 알림 문구(`alarms/messages`)·일정(`schedule`·`plan`)도 같다.
- 화면 순서: 근무조(시작 시각 순) → 점심당번 → 장중관제(키 순). 출근표 입력 표·CSV 열과 관리 화면 부서 목록의 출근조도 저장한 부서 출근조 순서가 아니라 지금 정의의 시작 시각 순(`boards.dept_keys`).
- **점심당번**: 생성(`generate._fill_lunch`)이 날짜마다 가장 이른 근무조(IT = 새벽)에 사유 없이 출근한 사람 전원을 넣는다(무작위 없음, 아무도 없는 날은 비우고 회차 화면에 경고). 시각은 정의가 아니라 부서(`Department.lunch_start`·`lunch_end`, 둘 다 있거나 둘 다 없음)에 두고 개인 알림·캘린더만 쓴다(IT 4부서 11:30~12:30, 마이그레이션 0022). 0022 는 그날(포함) 이후의 배포됨·생성됨 회차와 `publish_undo` 의 새벽 행에도 점심당번을 채웠다. 근무 변경 창의 "점심당번도 같이 넘기기"(기본 켬)가 근무조를 넘길 때 From 의 점심당번도 To 에게 넘긴다(`changes._carry_lunch`, 기록은 `cell="lunch"`).
- 장중관제 배정은 `DutyAssignment(cell="slotN")` 행으로 저장한다(읽을 때 계산하지 않는다). 관제 칸당 한 명은 조건부 unique 제약이 보장한다. 점심당번도 같은 표(`cell="lunch"`, 하루 여러 명)다. 배포 때 지운 행은 `publish_undo`에 `["c", 회차, 날짜, 멤버, 출근조, 사유]`(출근표, 사유 칸이 없는 옛 다섯 칸 행도 읽는다)·`["a", 회차, 날짜, 멤버, 칸]`(배정)로 보관한다.
- 근무표는 슈퍼유저가 관리 화면 "근무표"에서 만든다(운영자 절차는 OPERATIONS.md "근무표 추가하기"). 근무 정의·부서 출근조·점심 시각·회차 단계는 관리 화면과 그 근무표 관리자의 [근무표 설정]이 같은 검사로 고친다(`forms.BoardShiftForm`·`BoardShiftFormSet`·`StepsForm`·`DeptShiftsForm`): 시각이 있으면 시작 < 끝(점심당번은 시각 없음), 이름·키 겹침 없음, 켜진 근무조 하나 이상, 켜진 근무조끼리 시작 시각이 다름, 관제 자격 근무조는 그 근무표의 근무조(켜진 관제는 켜진 근무조만, 하나 이상), 근무조를 꺼도 부서마다 켜진 입력 근무조가 하나 이상, 자격은 장중관제만·기본 알림은 근무조만, 이름은 `date`·`day`·`(`·줄바꿈 금지(CSV 열 이름). **저장한 정의는 키를 바꾸거나 지울 수 없고** '사용'을 끈다(관리 화면은 키 칸을 잠그고 지우기 칸이 없다. 모델도 `BoardShift.clean`·`delete` 로 막는다, 쿼리셋 일괄 삭제만 예외). code 는 만들 때 짧은 영문 소문자(`Board.clean`)이고, code(주소 `?board=` 와 기억한 근무표 `RosterPref.boards` 의 열쇠)는 만든 뒤 바꾸지 않으며, 근무표는 지우지 않는다. 회차 단계 칸은 저장된 근무표에서도 고친다(진행 중인 회차의 단계 이름·버튼이 바로 바뀌고, 끈 단계에 회차가 남으면 저장 뒤 "'마감' 단계에 회차 1개가 남아 있습니다. 회차 화면에서 다른 단계로 옮기세요.", `board_settings.stranded`). 단계 이름은 비울 수 없고 줄바꿈 금지·서로 다름, 켠 단계에서 나오는 버튼 글자가 비거나 서로 겹치는 이름도 막는다(`forms.StepsForm`, 관리 화면 `BoardForm` 은 그것을 물려받는다, `Board.bad_buttons`·제약 `board_step_names_set`). 부서 수 제한은 없다. 어느 근무표의 부서든 입력 담당자를 고를 수 있다(처음 고를 때 입력 그룹이 생긴다). 새 부서의 출근조는 중립 이름(근무조 1~4)으로 고르고 저장 때 그 근무표의 켜진 근무조인지 본다.
- 대상 날짜는 회차 기간의 월~금이다. 그중 **건너뛰는 날**(`boards.skip_reasons(period)`·`skip_dates`)은 만드는 도구가 비워 둔다: 입력 표(그날 행 잠금, 까닭 표시), CSV(그날 이름이 있으면 오류, 내려받기는 빈 줄), 생성(관제·점심당번), 빈 날 검사(`periods.missing_dates`·입력 현황). 건너뛰는 날 = 근무 없음 날 메모(늘) ∪ 켜진 휴장일(`Period.skip_holidays` 인 회차만. 2단계 마이그레이션 전 회차는 거짓, 새 회차는 참). 이미 들어 있는 행은 지우지 않고 보인다(휴장일을 나중에 추가했을 때).
- **남는 IT 가정**(알고 둔다): 칸 키 `shifts.KEYS` 는 근무조 4개·관제 10칸 고정(PRINCIPLES 2026-11-15). 사용법 영상은 IT 화면으로 찍었다(글 도움말은 근무표마다 단계 이름을 보인다). 통계는 관제 있는 근무표 중 id 가 가장 작은 하나(`views/manage.stats_view` 의 `ponytail:` 주석, 관제 있는 근무표가 둘째로 생기면 고르기). `boards.it_board()`(code `it` 로 IT 근무표를 찾는다)는 정의만 남고 앱 코드는 부르지 않는다(테스트·사용법 영상 가짜 데이터용, `git grep -n "it_board()" -- duty ':!duty/migrations'` 는 정의 한 줄). 부서 없는 계정의 기본 근무표(알림 규칙 검사 `services/alarms.rule_board`·규칙 폼)는 `boards.home(user)` 다.

## 휴장일·메모·사유

- **휴장일**(`Holiday`, 모든 근무표 공통): `services/holidays.sync(today)` 가 (가장 이른 회차의 해, 올해 중 이른 해)~(내년, 가장 늦은 회차의 해 중 늦은 해)의 `market_days.holidays_for` 날짜 중 표에 없는 것만 `source=auto` 로 넣는다(있는 행·끈 행은 건드리지 않고, 라이브러리에서 사라져도 지우지 않는다). 부르는 곳은 작업자 매 바퀴 맨 앞, 회차 저장(`periods.save_draft`) 뒤, 생성 — 화면 GET 은 부르지 않는다. 슈퍼유저는 관리 화면 "휴장일"에서 임시공휴일을 추가(`manual`)하거나 끈다(`active`, 지우기는 막음). 읽기는 `holidays.closed(start, end)`(켜진 것만, 주말 포함). 날짜 칸 맨 위에 이름이 보이고(`.hol`), 영업일 기준 알림(`alarms/schedule.bizdays_back`)은 켜진 휴장일을 영업일에서 뺀다(회차와 무관). 휴장일을 고쳐 발송일이 바뀌어도 이미 보낸 알림은 다시 보내지 않는다.
- **메모**(`Memo`, `services/memos.py`): (근무표, 범위, 날짜)에 하나. 범위는 날(`day`)·주(`week`, 월요일에 저장)·달(`month`, 1일에 저장). 쓰기는 그 근무표 관리 그룹만(`[메모]` 팝업). 메모 글은 노란 상자(왼쪽 띠, `--memo-*` 색, 밝게·어둡게 따로)로 그린다. 날 메모는 날짜 칸 맨 위, 주 메모는 표 위(월간은 그 주 행 아래에 "M/D 주 메모:" — 그 주 월요일), 달 메모는 표 아래. 날 메모의 **근무 없음**은 그날 칸 전체를 글로 덮는다: 저장할 때 배정이 있으면 확인창이 지워질 인원수를 보여 주고 본 인원수를 `confirm` 으로 보낸다(그사이 인원이 바뀌었으면 서비스가 새 인원수로 다시 묻는다). 그 뒤 그날의 모든 배정을 지운다(배포 회차 행은 지운 것마다 `ChangeLog`, 변경 알림은 평소처럼. 배포 전 회차 행은 기록 없이). 그날은 근무 변경이 막히고(`changes._owner`), 배포 취소로 되살아나지도 않는다(`publish._restorable`). 메모 지우기는 팝업 맨 아래 "위험 구역"에 있다. 메모를 지우거나 근무 없음을 끄면 빈 날이 되고 넣기로 채운다.
- **사유**(`Commute.reason`: 휴가·출장·교육, 빈 값 = 없음): 사유는 **사람-날 단위**다: 그날 어느 근무조 배정에든 사유가 있으면 그 사람의 그날 전체를 근무로 치지 않는다(`roster.Day.excused`) — 그날의 개인 알림(근무조·관제·점심당번 모두), 보고서 요약 인원, 캘린더 일정, 통계(새벽·야간 횟수, 관제 배정 횟수. 점심당번은 원래 횟수에 넣지 않는다)에서 빠지고, 점심당번 채우기·관제 생성 후보에서도 빠진다. 보고서·알림에는 "이름(휴가)"로 쓴다. 근무표 화면(주간·월간·하루)에서는 그 사람이 보이는 모든 칸(관제·점심당번 칸 포함)에 "이름(휴가)" 전체를 취소선·회색(밝게·어둡게, 강조 칠 위 모두 배경과 대비 4.5:1 이상)으로 그리고(`_labels.html` 의 `.exc`, 색은 `base.html` 의 `--exc`), 변경 내역 표시를 끄면 빠진 사람처럼 숨긴다(`views/roster._visible`). 근무 변경 창의 지금 사람 목록에는 늘 남아 사유를 고칠 수 있다. 입력 표·CSV 는 "이름(휴가)"로 읽고 쓰고(`csv_io.split_reason`·`join_reason`), 그래서 이름이 (휴가)·(출장)·(교육)으로 끝나는 계정은 만들 수 없다(마이그레이션 0018 도 그런 계정이 있으면 멈춘다). 근무 변경 창의 [사유 저장]은 `changes.set_reason`: 사람은 그대로라 기록은 before = after 에 `reason_before`·`reason_after` 를 남기고, 변경 알림은 없다(이력에만 "가 → 가(휴가)"). 그 사람이 그날 당번 칸에 남아 있으면 빼지 않고 경고만 한다(점심당번 칸은 "바꾸거나 빼세요", 관제 칸은 비울 수 없어 "바꾸세요"). 맞교환에서는 사유가 사람을 따라간다.

## 역할

권한은 `auth.Group` 멤버십으로만 판단한다(`perms.py`: `admin_boards`·`is_board_admin`·`is_admin`·`managed_departments`·`can_edit`·`assert_can_edit`). Django permissions와 "스태프 권한"(`is_staff`)·슈퍼유저는 근무표 권한에 쓰지 않는다(`is_staff`는 관리 화면 출입 조건 `admin.site.has_permission`에만 남는다).

|---|---|
| 멤버(로그인한 누구나) | 근무표·내 근무 조회(여러 근무표 겹쳐 보기 포함), 내 근무표의 오늘·미래 근무 변경, 내 알림·캘린더 |
| 출근표 입력 담당(부서 입력 그룹 멤버, `Department.input_group`) | 취합 중인 회차에 자기 부서 출근표 입력 |
| 근무표 관리자(근무표 관리 그룹 멤버, IT = "IT 근무표 관리") | 그 근무표의 회차 관리·생성·배포, 메모(근무 없음 포함), 통계, 변경 이력, 지난 날짜 수정, 그 근무표 전 부서 출근표, [근무표 설정](사람(관리자 계정 제외: 추가·이름·구분 고치기·퇴사·다시 재직·계정 발급과 비밀번호 초기화), 관리자 넣기·나 자신과 퇴사자 빼기, 입력 담당자, 근무 정의와 부서, 회차 단계). 회차 뷰는 `_period(request, pid)`가 검사(아니면 404). 메뉴 [회차]·[이력]은 어느 근무표든 관리자면 보인다. [통계]는 slot* 정의가 있는 근무표의 관리자에게만 보인다(`perms.stats_boards`). 통계 화면은 그중 id가 가장 작은 근무표를 보여 주고, 없으면 403이다(통계의 근무표 고르기는 관제 있는 근무표가 둘이 되면) |
| 슈퍼유저 | Django 관리 화면: 사용자("그룹" 칸으로 근무표 관리자 지정, 재직 중인 다른 관리자 빼기)·부서(점심 시각 포함)·휴장일·근무표와 근무 정의(추가·편집)·그룹(이름·멤버 보기)·계정 발급(관리자 계정의 발급·초기화·퇴사·이름 고치기는 여기서만)·로그인 잠금 해제·알림 설정. 근무표 관리자 권한은 자동으로 받지 않는다(관리 그룹에 넣어야 한다) |

바로가기(#people·#admins·#assignees·#shifts·#steps), 칸마다 따로 저장하고 그 칸 앵커로 돌아오며 결과 메시지는 `messages` 의 `extra_tags`(칸 id)로 그 칸 제목 아래에 그린다(`base.html` 맨 위에는 칸 태그가 없는 메시지만 그리므로 칸 태그는 [근무표 설정]에서만 쓴다. 다른 화면에서 쓰면 메시지가 보이지 않는다). 서비스 함수마다 첫 줄 `_require_admin`, 받은 부서·사람·근무 정의가 그 근무표 것인지 다시 본다(범위 밖이면 `PermissionDenied`, 뷰는 404. 근무 정의 formset 은 `instance=board`, 부서 폼은 그 근무표 부서만 만들고 다른 id·부서 칸이 섞인 POST 는 404). 관리자 넣기 후보 = 재직 중인 그 근무표 사람 + 부서 없는 계정. 관리자 빼기는 **나 자신이나 퇴사한 관리자만**(재직 중인 다른 관리자 빼기는 슈퍼유저 — 빼고 나서 그 계정을 다루는 우회를 막는다). **재직 관리자는 근무표마다 한 명 이상**(`boards.left_without_admin`): 앱의 빼기와 관리 화면 사용자 편집(관리 그룹을 빼거나 재직을 끔, 칸 오류)·지우기(`UserAdmin.get_deleted_objects` 가 보호 목록에 까닭을 넣어 한 명 지우기·일괄 지우기 모두 막는다)가 같은 검사를 쓴다. 근무 정의와 부서는 [저장] 하나로 한 트랜잭션(`save_shifts`): "부서마다 켜진 입력 근무조 하나 이상"은 이번에 저장할 부서 출근조로 보고, 부서에서 근무조를 빼는데(같은 저장에서 끄면서 빼도) 배포 전 회차에 그 출근표가 있으면 저장하지 않고 행 수를 보인 뒤 [그래도 저장](본 행 수를 `confirm` 으로, 그사이 바뀌면 다시 묻는다), 부서 칸은 그린 때 체크박스로 보인 키를 숨은 칸 `d-<부서 코드>-shown` 으로 보내고 저장은 그 밖의 저장된 키(꺼진 근무조, 그린 뒤 다른 관리자가 켠 근무조)를 그대로 남긴다(`DeptShiftsForm.shown`. 보낸 값은 참고일 뿐 저장된 키를 남기게만 하고 키를 더하지는 못한다. 확인·오류로 다시 그릴 때는 처음 보낸 값을 그대로 싣는다), 생성됨 회차에 배정이 남은 관제 정의를 끄면 저장하고 경고, 켜진 근무조 중 어느 부서에도 없는 것이 있으면 경고 상자와 [부서 저장]. 단계 칸은 맨 아래 접힌 칸이고 저장된 단계·실제 버튼 글자 미리보기와 저장 확인창이 있다. 사람 칸(`#people`, 맨 위): 그 근무표 부서 사람 표(계정 열 = 발급 전(쓸 수 있는 비밀번호 없음)·첫 로그인 대기(`must_change_password`)·사용 중), 줄마다 `<details>`("고치기 · 비밀번호 · 퇴사", 발급 전 줄은 초기화가 없어 "고치기 · 퇴사") 안에 이름·구분 고치기와 위험 구역([비밀번호 초기화]·[퇴사]), 접힌 퇴사자 목록([다시 재직]), 사람 추가(아이디 `[a-z][a-z0-9_]{1,29}`, 칸은 대문자 자동 변환·자동 고침 끔, 다음 빈 번호 `<code><nn>` 를 미리 넣음 `board_settings.next_username`, 구분은 켜진 장중관제 정의가 있는 근무표만). 사람 함수(`set_person`·`set_active`·`issue`)의 대상은 그 근무표 부서 사람 중 슈퍼유저·나 자신·관리자 계정(어느 근무표든)이 아닌 사람만(`board_settings.locked_ids`·`_person`, 아니면 `PermissionDenied`·뷰 404). 화면은 관리자 계정 줄을 '관리자 계정은 슈퍼유저에게', 내 줄을 '내 비밀번호는 메뉴 [비밀번호]에서'로 잠근다. 퇴사는 오늘 이후 칸(`future_cells`: 그날의 주인 회차의 배포 행 + 배포 전 회차 행)이 있으면 그 줄 아래 목록과 [그래도 퇴사 처리](본 칸 수 `confirm`)를 거치고, 퇴사 뒤 칸 메시지에 링크 목록(배포된 날 = 하루 화면, 배포 전 = 입력 표). 계정 발급·초기화(`issue`, 한 트랜잭션, 같은 사람이 두 번 와도 한 번만 발급, 퇴사자 거부)는 redirect 없이 그 자리에서 다시 그려 사람 칸 맨 위 결과 상자에 임시 비밀번호를 보인다(응답 본문에만, 세션·메시지·로그·`LogEntry` 에 없음, 응답은 `no-store`). 줄의 [계정 발급]과 일괄 발급 체크박스는 발급 전 줄에만(체크박스는 표 밖 빈 폼 `issue-many` 에 `form` 속성으로 묶음, [선택한 사람 계정 발급]은 발급 전 줄이 있을 때만), [비밀번호 초기화](확인창)는 발급 전이 아닌 줄에만 있어 첫 로그인 대기인 사람의 재발급도 이 버튼으로 한다(쓰는 중인 사람을 확인창 없이 한꺼번에 로그아웃시키지 않는다). 발급 버튼과 [다시 재직]은 누르면 꺼진다(`event.submitter`).
- 쓰기마다 로그 한 줄 `board <code>: <동작> <대상 아이디·부서 코드·근무표 code> by <아이디>` 와 Django `LogEntry` 한 줄(대상 사람·근무표, `object_repr` 는 아이디·code, `change_message` "근무표 <code>: <동작>")을 남긴다. 실명은 넣지 않는다(`log_actions` 는 `object_repr` 에 실명을 넣어 쓰지 않는다, `board_settings._audit`). 관리 화면에서 그 사람·근무표 편집 페이지의 [기록]으로 본다(첫 화면 "최근 작업"은 로그인한 슈퍼유저 자신의 작업만 보인다).
- 저장된 부서의 근무표는 바꿀 수 없다(`admin.DepartmentForm` 의 board 칸이 읽기 전용, 새 부서만 고른다. 옮기기는 필요해지면 별도 기능). 저장된 부서의 코드도 읽기 전용이다(기본키라 바꾸면 새 부서가 생긴다). 부서 순서(`Department.order`, 기본 99 = 맨 뒤)가 근무표 화면 부서 필터의 순서다.
- 사람의 부서를 바꿔 근무표가 달라지면 `accounts.on_department_change(user, old_department_id)`가 개인 알림 발송 기록을 정리한다. 지금 이 함수를 부르는 곳은 관리 화면 사용자 저장(`UserAdmin.save_model`) 하나뿐이다. 부서를 바꾸는 다른 길을 만들면 그 길에서도 반드시 불러야 한다.

## 회차

```
작성 중 ⇄ 취합 중 ⇄ 마감  ──생성──▶ 생성됨 ──배포──▶ 배포됨
   ▲________________________________│  (상태 바꾸기)    │
                                     ◀────배포 취소─────┘ (가장 최근 배포만)
```

- **회차 단계는 근무표 설정이다**(`Board.use_draft`·`use_close`·`step_*`). DB 상태 다섯 개는 그대로이고 작성 중·마감은 끌 수 있으며, 화면 이름(`Period.status_label`, 상태 기록, 단계 띠)은 근무표의 단계 이름이다(끈 단계도 이름이 있어 남은 회차·기록이 이름으로 보인다). IT = 둘 다 켬(작성 중·취합 중·마감·생성됨·배포됨), 시장운영실 = 둘 다 끔(입력 중·확정·배포됨. 마이그레이션 0023 이 옛 `input_mode=direct` 근무표에 넣은 값). 규칙은 쿼리 없는 `Board` 메서드다: 새 회차는 `first_step()`(작성 중을 쓰면 작성 중, 아니면 취합 중, `periods.save_draft`), 기간은 `editable()`(작성 중, 그리고 작성 중을 안 쓰면 취합 중에서도), 생성은 `generate_from()`(마감을 쓰면 마감, 아니면 취합 중) 또는 생성됨에서, "다른 상태로 옮기기"는 `move_targets()`(켠 배포 전 단계끼리, 끈 단계에 남은 회차도 켠 단계로. `periods.move` 는 배포됨 → 같은 상태 → `move_targets` 순으로 검사한다). 회차 화면 버튼 글자는 단계 이름에서 나온다(`step_buttons`: "취합 중" → [취합 열기]·[취합 마감], 장중관제가 있으면 [장중관제 생성]·[재생성], 없으면 생성됨 이름 끝의 "됨"을 뗀 말("됨"으로 끝나지 않으면 이름 그대로, 예: [확정]), 취합 중 이름이 " 중"으로 끝나지 않으면 열기·마감은 "'<이름>'(으)로" 꼴, 생성됨에서 옮길 곳이 하나뿐이면 상자 대신 [확정 취소] 같은 버튼). 바꿀 수 있는 이름 뒤 조사는 `shifts.josa` 로 고르고, 확인창(인라인 JS) 안의 이름 글은 `escapejs` 로 넣는다. 마감을 안 쓰는 근무표는 취합 중 회차 화면에 부서마다 [표 입력] 버튼과 생성 버튼이 나란히 있다(빈 평일이 있으면 첫 [표 입력]이, 없으면 생성 버튼이 진한 버튼). 1단계에서 "장중관제가 있다"는 임시 기준으로 정한다: 마감을 쓰는 근무표는 [장중관제 생성]·[재생성]·[생성 방식](지금 글 그대로)·배정 횟수 표, 마감을 안 쓰는 근무표는 관제 정의·배정이 남아 있어도 [확정]·[확정 취소]만(main 과 같은 화면).
  - **모든 근무표에 같은 규칙**(근무표 통합 2단계): 버튼 글자·[재생성]·[생성 방식](숫자·자격 문장은 관제 정의에서 만든다, `shifts.gen_help`. 칸마다 자격 유형이 다르거나 일부 칸만 유형이 비어 있으면 유형을 합치지 않고 "칸마다 정한 유형이고 …"·"사람을"로 적는다)·배정 횟수 표는 켜진 장중관제 정의라는 데이터로 정한다. 빈 평일은 생성을 막지 않고 경고만 한다. 회차 화면 켠 취합 중·마감에 "⚠ 출근표가 비어 있는 날: <부서 이름> n일(11/16~11/20) · …"(이어진 평일은 묶는다, `shifts.day_spans`), 그 상태에서 생성할 수 있을 때만 "[<생성 버튼>] 버튼은 누를 수 있지만 그날 그 부서는 근무자가 없습니다."를 붙인다(IT 취합 중에는 붙이지 않는다). 빈 날이 있으면 생성 버튼은 테두리 버튼이고 누르면 "출근표가 비어 있는 부서가 있는 날이 N일 있습니다. …계속할까요?" 확인창(빈 날이 없으면 확인창 없음), 생성 뒤 메시지에 부서별 빈 날. 부서별 입력 현황은 모든 근무표에 부서 이름으로 보이고 취합 중이면 부서마다 [표 입력] 버튼(누를 자리 44px 이상)이 붙는다. [기간 저장]은 기간을 줄일 때만 확인창을 띄운다. 생성됨에서 나가는 확인창은 하나이고 그 회차에 **실제로 있는 배정**으로 만든다(`leave_generated_confirm`: "생성 결과(장중관제·점심당번 배정)가 지워지고 출근표는 그대로 남습니다. 계속할까요?", 하나만 있으면 그것만, 없으면 "출근표는 그대로 남습니다. 계속할까요?"), 옮기기 상자 설명도 같은 말. 확인창 글은 `escapejs` 로 넣는다. 끈 단계에 남은 회차는 "이 단계는 지금 쓰지 않습니다. 아래 [다른 상태로 옮기기]를 눌러 옮기세요." 한 줄과 펼쳐진 상자. 오류·안내 글은 그 근무표의 **켠** 단계 이름을 쓴다("기간은 '작성 중' 단계에서만…", "'입력 중'(으)로만 옮길 수…", "'마감'인 회차만 장중관제 생성할 수…", "'확정'인 회차만 배포할 수…", "'생성됨' 상태로 바꿨습니다. 근무표 화면에는 배포한 뒤에 보입니다."). 입력 표의 [← 회차 화면으로] 링크는 그 근무표 관리자에게만.
  - 단계 칸(켜고 끄기·이름)은 관리 화면 "근무표"와 [근무표 설정] "회차 단계" 칸에서 고친다(근무표 통합 3단계에서 1단계 임시 기준을 지우며 열었다). 단계를 켜고 끄는 것은 막지 않는다. 끈 단계에 남은 회차는 저장 뒤 안내와 회차 화면 한 줄이 알리고 "다른 상태로 옮기기"로 켠 단계로 옮긴다.
- 회차는 근무표 하나에 속한다(관리하는 근무표가 여럿이면 만들 때 고른다). 회차는 그 근무표가 켠 배포 전 단계끼리 `periods.move`로 오간다(`Board.move_targets`). 생성됨에서 나가면 장중관제·점심당번 생성 결과(그 회차 `DutyAssignment` 전부)를 지우고 출근표는 남는다. 기간은 `Board.editable()`이 돌려주는 단계에서 고친다(작성 중을 끈 근무표는 취합 중에서도)(줄이면 기간 밖 행을 지운다). 기간 저장(`periods.save_draft`)은 상태를 DB 에서 다시 읽고(`select_for_update`) 이름·기간만 저장한다(낡은 객체가 상태·seed 를 되돌리지 못하게). 새로 만들거나 기간을 고칠 때 같은 근무표의 다른 배포 전 회차와 겹치면 막는다(배포 취소로 돌아온 회차는 겹칠 수 있고, 배포할 때 덮어쓰기로 정리된다).
- 배포되지 않은 회차는 [회차 삭제]로 지울 수 있다(출근표·생성 결과·상태 기록까지). 근무 변경 기록이 남은 회차(배포된 적 있음)는 기록 보존을 위해 지울 수 없다.
- 생성됨은 [생성]으로만, 배포됨은 [배포]로만 들어간다. 상태가 바뀔 때마다 `PeriodEvent`(언제·누가·무엇에서 무엇으로·메모)를 남긴다.
- **출근표 입력**(`services/collect.py`): 회차와 같은 근무표의 부서만 받는다. 표에서 직접 고치거나 CSV를 올린다. CSV는 UTF-8(BOM)→CP949 순으로 읽고, 하나라도 틀리면 아무것도 반영하지 않고 (위치, 사유)를 보여 준다. 올리면 그 부서의 회차 출근표 전체를 파일 내용으로 바꾼다. 저장할 때 꺼진 근무조 정의의 행만 그대로 두고, 부서 출근조에서 뺀 근무조의 행은 지운다(`collect._kept_keys`). 취합 중 회차의 입력 표에는 근무표와 상관없이 주마다 **[2주 전 기준으로 채우기]**(입력 근무조가 3개일 때만: 2주 전 그 주 월~금에 근무로 친 날이 가장 많은 근무조(같으면 먼저 나온 것)를 보고 이른 ↔ 늦은, 나머지·근무가 없던 사람은 가운데. 기준 주에 근무로 친 사람이 아무도 없으면 모두 가운데가 되므로 채우지 않고 오류)와 **[지난주와 같게]**(지난주 같은 요일의 근무조, 사유는 옮기지 않음)가 있다(`collect.fill_week`). 버튼 줄의 주 머리는 회차가 주 중간에 시작해도 그 주 월요일이다. 기준은 회차 기간 안이면 화면의 표(저장 전 고친 것 포함), 밖이면 배포된 근무표(그날의 주인)다. 지금 재직하는 그 부서 사람만 넣고(그날 꺼진 근무조 정의에 행이 남은 사람은 빼고) 건너뛰는 날은 비운다. 누르면 그 주의 줄만 다시 그려 보여 주고(바뀐 칸 색칠) 저장은 [표 저장]으로만 한다. 칸은 여러 줄 칸(textarea, 이름이 많으면 줄바꿈해 다 보인다. 쉼표·줄바꿈 모두 구분자)이고, 칸에서 Enter 는 저장이다(폼 맨 앞의 화면 밖 저장 버튼. Shift+Enter·한글 조합 중 Enter 는 그대로).
- **생성**(`generator.py`, `services/generate.py`): 빈 평일(그 근무표 부서 중 출근표가 없는 평일)은 모든 근무표에서 막지 않고 부서별 빈 날을 경고 한 줄로 알린다. 장중관제는 그 회차 출근 행이 하나도 없는 날을 빼고 만든다(일부 부서만 빈 날은 다른 부서 사람으로 채우고, 후보가 모자라면 지금처럼 못 채운 칸 표). 생성은 두 가지를 한다. 장중관제: 칸 목록은 그 근무표의 관제 정의(`slot_defs`, 키 순)이고, 관제 정의가 없는 근무표는 관제 생성을 건너뛴다. 점심당번: 켜진 점심당번 정의가 있으면(관제 정의가 없어도) 날짜마다 가장 이른 근무조에 사유 없이 출근한 사람 전원으로 채운다(`_fill_lunch`, 무작위 없음, 아무도 없는 날은 비우고 경고).
  1. 날짜마다 자격자가 적은 칸부터, 그날 아직 안 받은 자격자 중 지금까지 배정이 가장 적은 사람(같으면 무작위). 한 사람 하루 한 칸.
  2. 최다·최소 차이(편차)가 2 이하가 될 때까지 많이 받은 사람의 칸을 적게 받은 자격자에게 넘긴다.
  - 후보는 그 근무표 부서의 재직자 중 관제 정의의 자격 구분(IT = 개발자)에 드는 사람이고, 횟수는 기간 중 한 번이라도 자격이 있던 사람끼리만 비교한다(통계도 같다). 회차 화면의 배정 횟수 표는 그 회차 출근표에서 칸별 자격(근무조·구분, 구분이 비면 전원)에 드는 사람이다(`stats.period_duty_counts`: 퇴사자도 자격 출근이 있으면 0회로 남고, 배정받은 사람은 배정 수로 남는다). 못 채우는 칸이 있으면 아무것도 쓰지 않고 날짜·칸을 보여 준다. 무작위 씨앗은 `Period.seed`에 남는다.
- **배포**(`services/publish.py`): 덮어쓰기 시작일 `S`를 고른다. 같은 근무표의 다른 배포 회차의 `[S, 이 회차 종료일]` 행과 이 회차의 `S` 이전 행을 지운다. 지운 행은 `Period.publish_undo`(JSON)에 보관한다. ChangeLog는 지우지 않는다.
- **그날의 주인**(`boards.owner(board, d)`, 여러 날은 `owners`): 그 근무표의 배포 회차 중 `overwrite_from ≤ d ≤ end_date`인 것 가운데 가장 최근에 배포한 것(배포 `PeriodEvent` 순번. 배포 이벤트가 없는 옛 회차는 그보다 오래된 것으로 보고 `published_at`·pk 순). 배포 때 지우는 규칙과 같은 결과라 행이 없는 날에도 주인이 있다. 근무 변경(`changes._owner`), 조회(`services/roster.py`의 `published_days`: 주인이 있는 평일마다 그 회차의 행. 행이 없으면 빈 칸이고 정기 알림·캘린더에는 넘기지 않는다), 변경 알림의 `_live`, 배포 미리보기가 모두 이 함수를 쓴다. 화면 칸의 변경 기록도 주인 회차 것만 보이므로 덮어쓰인 회차의 ChangeLog는 숨겨진다.
- **배포 취소**: 그 근무표에서 가장 최근에 배포한 회차만. 보관한 행을 되살리고 회차는 생성됨으로 간다. 중간 회차는 뒤 배포부터 차례로 취소한다. 배포 뒤 수정은 회차 데이터에 남지만, 배포 취소 때 그 시점의 ChangeLog 최대 번호를 `Period.log_floor`에 적고, 그 이하 기록은 다시 배포해도 화면·알림에 쓰지 않는다(기록은 남는다). 순서는 근무표마다 `PeriodEvent` 순번으로 정한다. 이 기능 전에 배포한 회차(`publish_undo` null)는 취소할 수 없다.

## 근무 변경

`services/changes.py` 한 곳에서 한다.

- 서비스 공개 함수(`change_cell`·`exchange`·`swap`, 첫 인자 다음에 근무표) 첫 줄에 `perms.assert_can_edit(user, board, d)`: 그 근무표 부서 사람이거나 그 근무표 관리자만 바꾼다. 오늘 이전 날짜는 그 근무표 관리자만. 출근표 입력의 지난 날짜 판단도 `perms.is_board_admin(user, period.board)`.
- 근무 변경 창(`changes.exchange`)의 기본은 **맞교환**: From(이 칸 사람)과 To 를 고르면, To 가 그날 같은 종류(출근조끼리·관제끼리) 다른 칸에 있으면 서로 바꾸고(`swap`), 없으면 From 대신 들어간다(`change_cell`). 출근조 칸의 넣기만·빼기만은 목록 끝 "(없음)"을 고르고 확인창을 거친다. 관제 칸은 바꾸기만이고, "맞바꾸지 않고 To 가 이 칸도 맡기"(`keep_other`)를 체크하면 To 의 다른 관제 칸은 그대로 두고 이 칸에도 넣는다(From 휴가로 한 사람이 두 칸을 맡을 때, "다른 관제 칸도 맡고 있습니다" 경고). 근무조는 한 사람 하루 하나라 이 칸이 없다. 새로 들이는 사람은 그 근무표 부서의 재직자만.
- 관제 자격이 안 맞거나 같은 날 다른 관제 칸도 맡으면 막지 않고 경고만 한다(대신 서기).
- 점심당번 칸은 넣기·빼기·교체만 한다(맞교환 없음). 근무조 칸에서는 사유([사유 저장])와 "점심당번도 같이 넘기기"가 함께 보인다.
- 모든 변경은 ChangeLog(`before`/`after`)에 남는다. 화면은 이를 이어 붙여 교체 `A>B`, 추가 `+B`, 제거(취소선)로 그린다. 사유만 바뀐 기록(before = after)은 이어 붙이지 않는다. 동시 수정은 먼저 저장한 쪽이 이긴다.

## 보일 근무표

- 근무표 화면(`/`)은 근무표 여러 개를 골라 한 표에 겹쳐 본다. 고른 목록 = `?board=a&board=b`(중복·빈 값은 버리고 없는 code 는 404) → `pick=1`(폼에서 골랐음)이고 `board` 가 없으면 내 근무표만 → 기억한 목록(`RosterPref.boards`, code 목록, 없는 code 는 버림) → 내 근무표(`boards.home(user)`: 내 부서의 근무표 → 내가 관리하는 첫 근무표 → 첫 근무표). 순서는 늘 `boards.in_order`(내 근무표 먼저, 나머지 id 순. 인사이동으로 내 근무표가 바뀌어도 읽을 때 다시 정렬), 기억도 그 순서이고 `[내 근무표]` 면 `[]`, 같으면 쓰지 않는다(`prefs.remember_boards`, 고르는 길은 `views/roster._selection` 한 곳). 기억은 `/` 에서만 읽고 쓴다: `/day/` 는 `?board=` 가 없으면 내 근무표 하나라 `?board=` 없는 알림 링크가 기억한 남의 근무표로 가지 않는다. 팝업(`/cell/`·`/memo/`)은 늘 근무표 하나(`?board=` 가 없으면 내 근무표, 둘 이상이면 404, `views/roster._board`).

- 유형 필터(개발자·직원)는 장중관제 정의가 켜진 근무표에만 보인다(근무표 화면과 보고서 규칙 폼 둘 다, `prefs.has_types`). 그런 근무표가 아니면 저장된 유형 값은 무시한다.
- 이력(`/changes/`)은 근무표 열과 `?board=` 필터가 있다(관리하는 근무표가 둘 이상일 때만 고르기가 보인다). 회차 목록도 관리하는 근무표가 둘 이상일 때 근무표 열이 보인다.

## 알림

- **내 근무가 바뀌면 알림**(`User.notify_changes`, 기본 켬): 작업자가 매분 `change_notice.tick`으로 아직 안 보낸 ChangeLog(`notified=False`)를 보고 당사자(From·To, 바꾼 본인 제외)에게 연결된 텔레그램·푸시로 보낸 뒤 `notified`로 표시한다. 오늘 이전 날짜·하루 넘게 밀린 기록은 보내지 않는다. 실패는 다시 보내지 않는다(로그만).
- 점심당번 문구는 "혼자인 당번 칸" 틀이다: 개인 알림 "점심당번 11:30~12:30"(부서 시각이 없으면 "점심당번", 그때는 시각 기준 규칙에서 빠지고 날짜 기준 규칙은 다음 날 00:00 에 만료), 보고서는 기존 줄 **뒤에** "점심당번 가, 나"(발송 창·만료·`same_day_notice` 계산에서는 뺀다. 점심당번만 고른 보고서 규칙은 저장 때 막는다. "전체"를 골라도 그 근무표의 스케줄이 점심당번뿐이면 같다), 변경 알림 위치 "점심당번". 사유가 있는 사람의 그날 배정은 개인 알림에서 모두 빠지고(취소 알림도 없음) 보고서에는 "가(출장)", 요약 인원은 사유 없는 사람만 센다.
- 사용자가 규칙(`AlarmRule`)을 만든다. 종류는 **개인**(내 근무) / **보고서형**(부서·유형·스케줄로 거른 그날 출근표). 시점은 근무 시작 N분 전 / N일 전 몇 시 / N영업일 전 몇 시. 채널은 텔레그램·웹 푸시. 보고서 규칙은 근무표 하나에 속한다(근무표 선택 칸은 근무표가 둘 이상일 때만 보이고, 하나뿐이면 그 근무표. 기본값은 `boards.home(user)` — 내 근무표가 맨 위, 나머지는 id 순). 개인 규칙은 내 부서의 근무표를 따른다. 기본 규칙(계정 첫 발급: 쓸 수 있는 비밀번호가 없고 로그인한 적도 없을 때)은 근무 정의의 "기본 알림 대상" 근무조로 만든다.
- 작업자가 매분 `alarm_runner.tick`: 근무표마다 그 근무표의 `published_days`(배정 있는 날만)와 그 근무표 규칙(개인 = 주인 부서의 근무표, 보고서 = `rule.board`)만 넘겨 그 근무표 정의로 `alarms.plan`을 따로 부른다(같은 날 다른 근무표 때문에 취소 알림이 나가지 않게). 지금 보낼 것을 `senders`로 보낸 뒤 `AlarmDelivery`를 남긴다(목적지별, **보낸 뒤에** 기록). 같은 내용은 `last_sent_hash`로 다시 보내지 않고, 근무가 바뀌면 변경·취소 알림을 보낸다. 규칙의 근무표(`board_id`)도 `RULE_FIELDS`에 있다. 관리 화면에서 사람의 부서를 바꿔 근무표가 달라지면 그 사람 개인 규칙의 오늘 이후 `AlarmDelivery`를 지운다(`accounts.on_department_change`).
- 발송 실패는 `Gone`(구독 삭제) / `Permanent` / `Temporary`·`RetryLater`(백오프 후 재시도)로 나눈다.
- 봇 토큰·푸시 키는 DB `AlarmSettings`(슈퍼유저가 관리 화면에서). 푸시 키는 비어 있으면 자동으로 만든다. 봇을 바꾸면 모든 텔레그램 연결 확인을 비운다.
- 텔레그램 연결: 사용자가 일회용 코드를 봇에 보내면 [연결 확인]이 `getUpdates`로 찾는다(파일 잠금으로 한 번에 하나).

## 캘린더 구독

- 사용자가 발급하면 `/calendar/<토큰>.ics` 주소가 **한 번만** 보인다. DB에는 SHA-256 해시만 둔다. 재발급하면 예전 주소는 죽는다.
- 피드는 로그인·CSRF 예외이고, 로그에서 경로를 지운다(`duty/logging.py`). 내용은 내 근무(배포된 것)이고 `duty/ics.py`가 글자로 만든다.
- 넣을 근무는 사용자가 고른다(`CalendarFeed.shifts`, 내 근무표의 근무조와 장중관제·점심당번. 빈 목록 = 전부). 주소는 그대로이고 재발급해도 고른 값은 남는다.
- 점심당번은 부서 점심 시각이 있을 때만 일정 하나("점심당번", UID `날짜-lunch-pk`). 사유가 있는 날은 그날 일정(관제·점심당번 포함)이 모두 빠진다.

## 작업자와 운영 파일

- `manage.py run_worker`: 1분마다 **휴장일 채우기**(`holidays.sync`, 없는 날짜만 넣어 가볍다) → **백업**(하루 한 번 `DUTY_BACKUP_HOUR` 이후) → **상태 점검**(5분마다, 바뀔 때만 장애 알림) → **알림**. 작업마다 예외를 따로 잡아 하나가 실패해도 나머지는 돈다. 파일 잠금으로 한 프로세스만 돈다.

## 화면 디자인

- Pico.css + `base.html`의 공통 스타일. NEXTRADE BI를 따른다: 로고·심볼은 `duty/static/duty/`의 원본 그대로(비율·색 변경 금지), 어두운 배경(다크 모드)은 흰색 단색(CSS `filter`). 지정 서체 Noto Sans KR(없으면 시스템 글꼴, 글꼴 파일은 싣지 않는다).
- 화면 모드: 상단 버튼으로 시스템·라이트·다크(기기마다 localStorage, `<html data-theme>`). 다크용 색은 `base.html` 맨 위 변수 두 곳(시스템 다크·직접 다크)에만 두고, 화면 규칙은 변수(`--chg`·`--logo-filter` 등)만 쓴다.
- 글씨 크기: 화면 모드 버튼 옆 [가]로 보통 → 크게(×1.15) → 아주 크게(×1.3)(기기마다 localStorage `duty-size`, `<html data-size="l|xl">`). 화면 모드와 같은 head 스크립트가 스타일보다 먼저 붙여 깜빡이지 않는다. `base.html` 의 `:root[data-size]` 두 줄이 Pico 의 화면 폭별 기본 크기(`--pico-font-size`)에 곱하므로, 화면 규칙은 rem·em 으로 쓰면 함께 커진다. 상단 계정 줄은 넘치면 아래로 내려간다(아주 크게 + 390px).
- 색: PURPLE `#2B1B40` = 주요 동작 버튼·현재 위치, RED `#E50038`(`--nxt-red`) = 로고·오류·위험 동작, 그리고 "오늘" 표시(달력처럼 읽힌다)만. 일반 버튼에 빨강을 쓰지 않는다(빨강 = 위험으로 읽힌다).
- 화면마다 다음 단계 하나만 채운 버튼, 되돌리기·다시 하기는 테두리 버튼, 지우기는 맨 아래 "위험 구역"(빨간 테두리) + 확인창.
- 메시지는 `messages` 종류대로 색과 기호(✓ 성공, ! 오류, ⚠ 경고)로 구분한다. 입력칸은 placeholder 말고 `<label>`(`form.labeled`).
- 모바일(390px): 메뉴는 줄바꿈(숨은 메뉴 없음), 주간 근무표는 하루씩 세로로, 검색·필터는 접힘. 필터 체크박스로 다시 불러올 때는 스크롤 위치와 펼침 상태를 되살린다(`_filters.html`, sessionStorage).
- 근무표 보기 설정(`RosterPref`: 고른 근무표 목록·부서·유형·스케줄·주간/월간·변경 내역 표시)은 사람마다 저장된다. 변경 내역을 끄면 `A>B`·`+B`는 지금 사람만, 빠진 사람(취소선)은 숨긴다. 화면을 바꾸면 PC 1400px·모바일 390px·다크 모드를 직접 본다.
- 근무표 칸에 올리거나 초점을 둔 배경(`--cell-hover`)은 옅게(보라 15%) 해서 그 위의 사유 회색 글씨도 대비 4.5:1 이상을 지킨다.
- [내 근무](`/me/`, `roster.member_schedule`): 시작일(기본 오늘, 지난 날도 된다)부터 종료일(비우면 마지막 배포 날)까지 근무가 있는 날마다 칸과 시각("정상 08:00~17:00", 점심당번은 부서 점심 시각이 있으면 "점심당번 11:30~12:30", 관제는 "장중관제 08:30~09:30", 사유는 "정상(휴가) 08:00~17:00"). 그 범위의 휴장일·근무 없음 날은 근무가 없어도 회색 줄(`li.off`)로 까닭(휴장일 이름, 근무 없음 메모 글 또는 "근무 없음")을 보인다. 근무 없는 보통 날은 빠진다.
- **엑셀 다운로드**(`duty/xlsx.py`, 읽기만): 열은 날짜·요일·근무표·칸·시간·이름·부서·사유, 배정 한 사람마다 한 줄(근무조·점심당번·장중관제, 사유 있는 사람도 사유 칸과 함께). 지금 배정만 넣고 변경 내역(A>B·빠진 사람)은 넣지 않는다. 줄은 `services/roster.export_rows`(화면과 같은 `published_days`·`display_order`, 필터는 화면의 `_keeper`·`_shown`)가 만들고, 날짜순·같은 날은 화면의 근무표 순서. 머리줄 굵게·고정, 자동 필터. 응답은 `Cache-Control: no-store`, 파일 이름은 RFC 5987 `filename*`(`당번표_<시작>_<끝>.xlsx`·`내근무_<시작>_<끝>.xlsx`, 내 근무에서 종료일이 비면 끝 = 마지막 근무 날).
  - 근무표(`/export.xlsx?start=&end=&board=…&dept=&type=&shift=`): 근무표 화면의 [엑셀 다운로드] 상자(`details.export`)가 지금 화면(주간 = 월~금, 월간 = 그 달 1일~말일, 고른 근무표, 필터)으로 채워져 열린다. 근무표 고르기는 화면과 같은 `_selection`(없으면 내 근무표, 없는 code 는 404, 아무것도 기억하지 않는다), 필터는 내 근무표 구역에만. 기간은 1년(365일 차이)까지, 잘못되면 한국어 오류와 함께 원래 화면(`next`)으로. 로그인한 누구나 볼 수 있는 근무표(배포된 날)를 받는다.
  - 내 근무(`/me/export.xlsx`): [내 근무] 폼의 [엑셀 다운로드](`formaction`)가 지금 칸 값(시작일·종료일·스케줄) 그대로 내 이름 줄만 받는다. 기간 한도는 없다(배포된 날만이라 끝이 있다).

## DB를 바꾸려면 (SQLite → MySQL 등)

코드는 ORM만 쓰므로 모델·서비스·화면은 그대로다. SQLite에 묶인 곳은 두 군데다.
- `services/backup.py`(백업·복원·검사): SQLite 파일 전용. DB 쪽 덤프·자동 백업으로 바꾸고, `health.py`의 "최근 백업" 점검을 맞춘다.
- 동시 수정: 지금은 `transaction_mode=IMMEDIATE`로 쓰기가 줄을 서서 `transaction.atomic()` 안의 "읽고 확인 → 쓰기"가 안전하다. 다른 DB에서는 서비스의 atomic 블록마다 읽는 행을 `select_for_update()`로 잠가야 한다(근무 변경, 출근표 입력, 생성·배포·배포 취소, 알림 기록 등).
- 작업자 한 개 보장은 파일 잠금이라 서버가 한 대일 때만 맞다.

## 보안·개인정보

- 로그인은 90일 유지된다(`SESSION_COOKIE_AGE`, 로그인할 때부터. 요청마다 늘리지 않아 화면을 열 때 세션 DB 쓰기가 없다). 비밀번호를 바꾸면 다른 기기의 로그인이, [계정 발급]으로 초기화하면 모든 로그인이 끊긴다.
- 로그인 5회 실패 시 그 아이디가 15분 잠긴다(django-axes). 비밀번호 변경의 '지금 비밀번호' 확인도 같이 센다.
- `config/wsgi.py` 가 Django 앞에 `duty/guard.py` 를 둔다: 본문 2MB 초과 413, 15초 안에 본문이 다 오지 않으면 408, 로그인·비밀번호 변경 POST 는 동시에 2개까지(넘치면 429). nginx 가 느린 연결을 먼저 받아 주고, 가드는 nginx 없이 돌 때(개발 PC)나 nginx 설정이 빠졌을 때의 한 번 더 막는 장치다.
- 로그인 잠금(axes)은 **아이디 + 접속 IP**(`AXES_LOCKOUT_PARAMETERS = [["username", "ip_address"]]`). 접속 IP 는 `duty/client_ip.py`: 127.0.0.1(nginx·tailscaled)에서 온 요청만 `X-Forwarded-For` 의 마지막 값을 믿는다. tailscaled 는 그 헤더를 실제 IP 하나로 덮어쓰고(서버에서 가짜 값을 넣어 보내 확인, 2026-11-19), nginx 는 `real_ip_header` 로 받아 `$remote_addr` 하나로 넘긴다. IP 하나만으로는 잠그지 않는다(한 IP 를 여럿이 쓰면 전원 차단).
- 로그인한 화면은 `Cache-Control: private, no-store`(`duty/middleware.py`). 로그 파일은 하루 50MB 를 넘으면 그날은 버린다(`duty/logging.py`).
- 관리 화면 액션 '계정 발급 / 비밀번호 초기화'의 초기화는 캘린더 구독·텔레그램·푸시 연결도 끊는다(탈취 의심 길). [근무표 설정]의 [비밀번호 초기화]는 연결을 남긴다(비밀번호 분실 길, `accounts.issue_account(revoke_links=False)` — 비밀번호가 바뀌어 로그인은 끊긴다). 퇴사(`accounts.deactivate`)는 재직을 끄고 쓸 수 없는 비밀번호로 모든 로그인을 끊고 연결을 모두 끊는다. 다시 재직(`accounts.reactivate`)은 퇴사와 같은 정리(관리 화면에서 재직만 끈 사람의 옛 비밀번호·연결도 끊는다) 뒤 재직을 켜서 [계정 발급]을 다시 해야 한다. 첫 발급(기본 알림 규칙)은 쓸 수 있는 비밀번호가 없고 로그인한 적도 없을 때만. 임시 비밀번호는 `accounts.temp_password`(헷갈리는 0·o·1·l·i 를 뺀 31자에서 `secrets.choice` 로 10자). 텔레그램은 `/start <일회용 코드>` 로만 연결한다(chat_id 직접 입력 없음).
- 백업 사본에서는 로그인 세션을 지우고 파일 권한을 600 으로 둔다.
- 실명은 커밋하지 않는다. 테스트는 가상 이름만 쓴다.
- [근무표 설정]에서 한 일은 로그 한 줄과 `LogEntry`(아이디·부서 코드·근무표 code 만)로 남는다. 근무표 관리자는 자기 근무표에 관리자를 넣을 수 있다(권한을 나눠 주는 권한을 슈퍼유저에서 근무표 관리자로 내린 결정, PRINCIPLES 2026-11-18). 막는 것: 다른 근무표 사람을 관리자로 넣기, 재직 중인 다른 관리자 빼기, 재직 관리자 0명. 근무표 관리자는 자기 근무표 사람 계정을 만들고 초기화한다(초기화한 비밀번호로 그 사람으로 들어갈 수 있는 것은 받아들인 위험, PRINCIPLES 2026-11-18). 관리자 계정·슈퍼유저·나 자신은 대상이 아니다. 다른 근무표 입력 그룹에 든 사람은 막지 않는다(그렇게 넣을 수 있는 것은 슈퍼유저뿐, 받아들인 위험).
- 로그·화면·메시지에 남기지 않는 것: 봇 토큰·푸시 개인키 원문(관리 화면은 끝 4자리만), 캘린더 토큰·피드 경로, 텔레그램 연결 코드, 푸시 endpoint, 메시지 본문.

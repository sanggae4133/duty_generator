# 아키텍처

코드가 지금 어떻게 생겼고 왜 그런지를 적는다. 기획은 [OVERVIEW.md](OVERVIEW.md), 설계 철학·결정 기록은 [PRINCIPLES.md](PRINCIPLES.md), 운영 명령은 [OPERATIONS.md](OPERATIONS.md), 개발 방법은 [DEVELOPMENT.md](DEVELOPMENT.md). 이 문서와 코드가 다르면 코드가 맞고, 이 문서를 고친다.

## 한눈에

```
브라우저 ──▶ gunicorn(duty-web) ──▶ Django 앱 duty ──▶ SQLite (data/db.sqlite3)
                                                         ▲
작업자 run_worker(duty-worker) ── 1분마다: 백업 → 상태 점검 → 알림 발송(텔레그램·웹 푸시)
캘린더 앱 ──▶ /calendar/<토큰>.ics (로그인 없이, 토큰으로)
```

- 앱 프로세스는 웹과 작업자 두 개뿐이다. 둘 다 같은 코드, 같은 `.env`, 같은 `data/`를 쓴다. 웹 앞에는 nginx 가 있다(설정 `deploy/duty-nginx.conf`, 느린 연결을 대신 받아 준다).
- 외부 연동 API는 없다. 바깥으로 나가는 것은 텔레그램 Bot API와 웹 푸시뿐이다.
- Tailscale Funnel로 공개된다(인터넷 → Funnel → nginx 127.0.0.1:8008 → gunicorn 127.0.0.1:8090). 모든 권한은 서버에서 검사한다(화면에서 버튼을 숨기는 것은 편의일 뿐).

| `duty/models.py` | 표 전부 | O |

## 데이터

```
Department ─< User(멤버 겸 로그인 계정)
Period ─< Commute(날짜·멤버·출근조)      Period ─< PeriodEvent(상태 기록)
       ─< ControlDuty(날짜·칸·멤버)       Period ─< ChangeLog(근무 변경 기록)
User ─ RosterPref · CalendarFeed · TelegramAlarmProfile · PushAlarmSubscription · AlarmRule ─< AlarmDelivery
AlarmSettings(한 행: 봇 토큰, 장애 알림 chat_id, 푸시 키)
```

- **User**: `username` = 멤버 코드. `department`가 없으면 근무표에 안 나오는 관리 전용 계정. `is_active`(재직)를 끄면 근무표 후보에서 빠지고 로그인도 막힌다. 지난 근무·기록·통계에는 남는다. 근무표 후보는 `User.objects.roster()`.
- 이름(`User.name`)은 전체에서 고유하다. `>` `,` 줄바꿈 금지, `+`로 시작 금지(변경 체인·CSV 문법 문자).
- 서비스는 트랜잭션에 들어가자마자 회차를 다시 읽어(`refresh_from_db`) 화면이 읽은 오래된 상태로 결정하지 않는다.
- 정해진 값만 받는 칸은 `choices` + DB `CheckConstraint`(SQLite엔 enum이 없다). 기록을 남겨야 하는 FK는 `PROTECT`라서 근무·기록이 있는 사용자·회차는 지울 수 없다(비활성화한다).
- SQLite는 WAL, 트랜잭션은 `IMMEDIATE`(쓰기가 서로 줄 선다). 웹은 gunicorn 워커 1개·스레드 4개.

## 근무조와 칸

칸(cell) 키 14개를 화면·기록·알림이 똑같이 쓴다.

- 출근조 4개: `dawn` 새벽, `normal` 정상, `dinner` 석식교대, `night` 야간. 한 사람은 하루에 출근조 하나(DB 제약).
- 장중관제 10칸 `slot0`~`slot9`(08:30~18:00). 자격 출근조는 08:30 칸 = 정상, 17:00 칸 = 석식교대, 나머지 = 정상·석식교대.
- 대상 날짜는 회차 기간의 월~금(휴장일 처리 없음).

## 회차

```
작성 중 ⇄ 취합 중 ⇄ 마감  ──생성──▶ 생성됨 ──배포──▶ 배포됨
   ▲________________________________│  (상태 바꾸기)    │
                                     ◀────배포 취소─────┘ (가장 최근 배포만)
```

- 작성 중·취합 중·마감끼리는 `periods.move`로 자유롭게 오간다. 생성됨에서 나가면 장중관제만 지우고 출근표는 남는다. 기간은 작성 중에서만 고친다(줄이면 기간 밖 행을 지운다). 새로 만들거나 기간을 고칠 때 다른 배포 전 회차와 겹치면 막는다(배포 취소로 돌아온 회차는 겹칠 수 있고, 배포할 때 덮어쓰기로 정리된다).
- 배포되지 않은 회차는 [회차 삭제]로 지울 수 있다(출근표·생성 결과·상태 기록까지). 근무 변경 기록이 남은 회차(배포된 적 있음)는 기록 보존을 위해 지울 수 없다.
- 생성됨은 [생성]으로만, 배포됨은 [배포]로만 들어간다. 상태가 바뀔 때마다 `PeriodEvent`(언제·누가·무엇에서 무엇으로·메모)를 남긴다.
- **출근표 입력**(`services/collect.py`): 표에서 직접 고치거나 CSV를 올린다. CSV는 UTF-8(BOM)→CP949 순으로 읽고, 하나라도 틀리면 아무것도 반영하지 않고 (위치, 사유)를 보여 준다. 올리면 그 부서의 회차 출근표 전체를 파일 내용으로 바꾼다.
- **생성**(`generator.py`, `services/generate.py`): 4개 부서의 평일이 다 차야 한다.
  1. 날짜마다 자격자가 적은 칸부터, 그날 아직 안 받은 자격자 중 지금까지 배정이 가장 적은 사람(같으면 무작위). 한 사람 하루 한 칸.
  2. 최다·최소 차이(편차)가 2 이하가 될 때까지 많이 받은 사람의 칸을 적게 받은 자격자에게 넘긴다.
  - 횟수는 기간 중 한 번이라도 자격이 있던 개발자끼리만 비교한다. 못 채우는 칸이 있으면 아무것도 쓰지 않고 날짜·칸을 보여 준다. 무작위 씨앗은 `Period.seed`에 남는다.
- **배포**(`services/publish.py`): 덮어쓰기 시작일 `S`를 고른다. 다른 배포 회차의 `[S, 이 회차 종료일]` 행과 이 회차의 `S` 이전 행을 지운다. 지운 행은 `Period.publish_undo`(JSON)에 보관한다. ChangeLog는 지우지 않는다.
- **조회**(`services/roster.py`): "배포됨 회차에 남아 있는 행"을 날짜로 읽는다. 그래서 한 날짜의 주인은 배포 회차 하나다. 덮어쓰인 회차의 ChangeLog는 화면에서 숨긴다.
- **배포 취소**: 가장 최근에 배포한 회차만. 보관한 행을 되살리고 회차는 생성됨으로 간다. 중간 회차는 뒤 배포부터 차례로 취소한다. 배포 뒤 수정은 회차 데이터에 남지만, 배포 취소 때 그 시점의 ChangeLog 최대 번호를 `Period.log_floor`에 적고, 그 이하 기록은 다시 배포해도 화면·알림에 쓰지 않는다(기록은 남는다). 순서는 `PeriodEvent` 순번으로 정한다. 이 기능 전에 배포한 회차(`publish_undo` null)는 취소할 수 없다.

## 근무 변경

`services/changes.py` 한 곳에서 한다.

- 오늘 이전 날짜는 어드민만(`perms.assert_can_edit_date`). 출근표 입력·근무 변경·배포에 모두 적용된다.
- 근무 변경 창(`changes.exchange`)의 기본은 **맞교환**: From(이 칸 사람)과 To 를 고르면, To 가 그날 같은 종류(출근조끼리·관제끼리) 다른 칸에 있으면 서로 바꾸고(`swap`), 없으면 From 대신 들어간다(`change_cell`). 출근조 칸의 넣기만·빼기만은 목록 끝 "(없음)"을 고르고 확인창을 거친다. 관제 칸은 바꾸기만. 새로 들이는 사람은 근무표 후보(재직·부서 있음)만.
- 관제 자격이 안 맞거나 같은 날 다른 관제 칸도 맡으면 막지 않고 경고만 한다(대신 서기).
- 모든 변경은 ChangeLog(`before`/`after`)에 남는다. 화면은 이를 이어 붙여 교체 `A>B`, 추가 `+B`, 제거(취소선)로 그린다. 동시 수정은 먼저 저장한 쪽이 이긴다.

## 알림

- **내 근무가 바뀌면 알림**(`User.notify_changes`, 기본 켬): 작업자가 매분 `change_notice.tick`으로 아직 안 보낸 ChangeLog(`notified=False`)를 보고 당사자(From·To, 바꾼 본인 제외)에게 연결된 텔레그램·푸시로 보낸 뒤 `notified`로 표시한다. 오늘 이전 날짜·하루 넘게 밀린 기록은 보내지 않는다. 실패는 다시 보내지 않는다(로그만).
- 사용자가 규칙(`AlarmRule`)을 만든다. 종류는 **개인**(내 근무) / **보고서형**(부서·유형·스케줄로 거른 그날 출근표). 시점은 근무 시작 N분 전 / N일 전 몇 시 / N영업일 전 몇 시. 채널은 텔레그램·웹 푸시.
- 작업자가 매분 `alarm_runner.tick`: 배포된 근무표를 읽어 `alarms.plan`으로 지금 보낼 것을 계산하고 `senders`로 보낸 뒤 `AlarmDelivery`를 남긴다(목적지별, **보낸 뒤에** 기록). 같은 내용은 `last_sent_hash`로 다시 보내지 않고, 근무가 바뀌면 변경·취소 알림을 보낸다.
- 발송 실패는 `Gone`(구독 삭제) / `Permanent` / `Temporary`·`RetryLater`(백오프 후 재시도)로 나눈다.
- 봇 토큰·푸시 키는 DB `AlarmSettings`(슈퍼유저가 관리 화면에서). 푸시 키는 비어 있으면 자동으로 만든다. 봇을 바꾸면 모든 텔레그램 연결 확인을 비운다.
- 텔레그램 연결: 사용자가 일회용 코드를 봇에 보내면 [연결 확인]이 `getUpdates`로 찾는다(파일 잠금으로 한 번에 하나).

## 도움말

- 메뉴 [도움말](`/help/`): 권한별 사용법 영상과 텔레그램·푸시·캘린더 설정 도움말. 로그인 화면의 [처음이세요? 사용법 보기]로 로그인 전에도 열린다: 그때는 로그인 안내 + 일반 사용자 영상(가짜 데이터)만, 담당자·관리자 영상과 설정 도움말은 로그인 뒤(권한 영상 주소는 로그인 화면으로 보낸다). 영상 목록·권한은 `duty/help.py`(`member` 모두, `manager` 출근표 입력 담당·관리자, `admin` 관리자).

- 영상은 `tools/help_videos/`(가짜 데이터 + Chrome 녹화)로 다시 만든다(DEVELOPMENT.md "사용법 영상 다시 만들기").

## 캘린더 구독

- 사용자가 발급하면 `/calendar/<토큰>.ics` 주소가 **한 번만** 보인다. DB에는 SHA-256 해시만 둔다. 재발급하면 예전 주소는 죽는다.
- 피드는 로그인·CSRF 예외이고, 로그에서 경로를 지운다(`duty/logging.py`). 내용은 내 근무(배포된 것)이고 `duty/ics.py`가 글자로 만든다.
- 넣을 근무는 사용자가 고른다(`CalendarFeed.shifts`, 새벽·정상·석식교대·야간·장중관제, 빈 목록 = 전부). 주소는 그대로이고 재발급해도 고른 값은 남는다.

## 작업자와 운영 파일

- `manage.py run_worker`: 1분마다 **백업**(하루 한 번 `DUTY_BACKUP_HOUR` 이후) → **상태 점검**(5분마다, 바뀔 때만 장애 알림) → **알림**. 작업마다 예외를 따로 잡아 하나가 실패해도 나머지는 돈다. 파일 잠금으로 한 프로세스만 돈다.
- 실행 중 생기는 파일은 전부 `data/`: `db.sqlite3`, `backups/`, `logs/`(web.log·worker.log, 자정 회전), 잠금·`.health.state`.
- 개발·운영 차이는 `.env` 값뿐이다. 셸 스크립트·타이머·logrotate는 없다. 업그레이드·롤백·복원은 OPERATIONS.md 의 명령으로 한다.

## 화면 디자인

- Pico.css + `base.html`의 공통 스타일. NEXTRADE BI를 따른다: 로고·심볼은 `duty/static/duty/`의 원본 그대로(비율·색 변경 금지), 어두운 배경(다크 모드)은 흰색 단색(CSS `filter`). 지정 서체 Noto Sans KR(없으면 시스템 글꼴, 글꼴 파일은 싣지 않는다).
- 화면 모드: 상단 버튼으로 시스템·라이트·다크(기기마다 localStorage, `<html data-theme>`). 다크용 색은 `base.html` 맨 위 변수 두 곳(시스템 다크·직접 다크)에만 두고, 화면 규칙은 변수(`--chg`·`--logo-filter` 등)만 쓴다.
- 색: PURPLE `#2B1B40` = 주요 동작 버튼·현재 위치, RED `#E50038`(`--nxt-red`) = 로고·오류·위험 동작, 그리고 "오늘" 표시(달력처럼 읽힌다)만. 일반 버튼에 빨강을 쓰지 않는다(빨강 = 위험으로 읽힌다).
- 화면마다 다음 단계 하나만 채운 버튼, 되돌리기·다시 하기는 테두리 버튼, 지우기는 맨 아래 "위험 구역"(빨간 테두리) + 확인창.
- 메시지는 `messages` 종류대로 색과 기호(✓ 성공, ! 오류, ⚠ 경고)로 구분한다. 입력칸은 placeholder 말고 `<label>`(`form.labeled`).
- 모바일(390px): 메뉴는 줄바꿈(숨은 메뉴 없음), 주간 근무표는 하루씩 세로로, 검색·필터는 접힘. 필터 체크박스로 다시 불러올 때는 스크롤 위치와 펼침 상태를 되살린다(`_filters.html`, sessionStorage).
- 근무표 보기 설정(`RosterPref`: 부서·유형·스케줄·주간/월간·변경 내역 표시)은 사람마다 저장된다. 변경 내역을 끄면 `A>B`·`+B`는 지금 사람만, 빠진 사람(취소선)은 숨긴다. 화면을 바꾸면 PC 1400px·모바일 390px·다크 모드를 직접 본다.

## DB를 바꾸려면 (SQLite → MySQL 등)

코드는 ORM만 쓰므로 모델·서비스·화면은 그대로다. SQLite에 묶인 곳은 두 군데다.
- `services/backup.py`(백업·복원·검사): SQLite 파일 전용. DB 쪽 덤프·자동 백업으로 바꾸고, `health.py`의 "최근 백업" 점검을 맞춘다.
- 동시 수정: 지금은 `transaction_mode=IMMEDIATE`로 쓰기가 줄을 서서 `transaction.atomic()` 안의 "읽고 확인 → 쓰기"가 안전하다. 다른 DB에서는 서비스의 atomic 블록마다 읽는 행을 `select_for_update()`로 잠가야 한다(근무 변경, 출근표 입력, 생성·배포·배포 취소, 알림 기록 등).
- 작업자 한 개 보장은 파일 잠금이라 서버가 한 대일 때만 맞다.

## 보안·개인정보

- 로그인 5회 실패 시 그 아이디가 15분 잠긴다(django-axes). 비밀번호 변경의 '지금 비밀번호' 확인도 같이 센다.
- `config/wsgi.py` 가 Django 앞에 `duty/guard.py` 를 둔다: 본문 2MB 초과 413, 15초 안에 본문이 다 오지 않으면 408, 로그인·비밀번호 변경 POST 는 동시에 2개까지(넘치면 429). nginx 가 느린 연결을 먼저 받아 주고, 가드는 nginx 없이 돌 때(개발 PC)나 nginx 설정이 빠졌을 때의 한 번 더 막는 장치다.
- 로그인한 화면은 `Cache-Control: private, no-store`(`duty/middleware.py`). 로그 파일은 하루 50MB 를 넘으면 그날은 버린다(`duty/logging.py`).
- 계정 초기화(재발급)는 캘린더 구독·텔레그램·푸시 연결도 끊는다. 텔레그램은 `/start <일회용 코드>` 로만 연결한다(chat_id 직접 입력 없음).
- 백업 사본에서는 로그인 세션을 지우고 파일 권한을 600 으로 둔다.
- 실명은 커밋하지 않는다. 테스트는 가상 이름만 쓴다.
- 로그·화면·메시지에 남기지 않는 것: 봇 토큰·푸시 개인키 원문(관리 화면은 끝 4자리만), 캘린더 토큰·피드 경로, 텔레그램 연결 코드, 푸시 endpoint, 메시지 본문.
